# R02.3 产品需求规格说明书（PRD）

- 版本：0.1；日期：2026-11-02
- 状态：产品基线草案；待用户研究、学科专家和试点确认
- 上游：R01.8、R02.1、R02.2；下游：R02.4–R02.6与R03

## 1. 目的、术语与优先级

本PRD定义产品范围、业务对象、功能需求、质量属性、异常流程和验收条件。需求编号是设计、实现、测试和审计的追踪主键。

优先级：P0=DC Circuit教学MVP必需；P1=首轮平台化；P2=后续扩展；OUT=当前明确不承诺。状态：BASELINE=设计基线；TBD=待决策；VERIFY=待验证。需求中的“必须”应转化为可测试行为。

## 2. 目标与非目标

### 目标
- 完成学生预测、操作、测量、分析、论证和提交的实验闭环；
- 完成教师布置、监控、审阅和评价的教学闭环；
- 提供可校验、可发布、可追溯的Experiment Package；
- 分离Scientific Model、Simulation Runtime、Renderer和Learning Workflow；
- 实验数据具备单位、时间、来源和版本元数据；
- 运行状态变更、异步计算和提交具备幂等、恢复和审计语义。

### 非目标
替代完整LMS/SIS；首期覆盖全部STEM学科；专业级通用CAE/CFD/FEA/SPICE；生产级真实设备控制；任意服务器端用户代码；无限制自主AI Agent；首期多人实时协同、VR/AR和插件市场；未经试点证明的学习效果提升承诺。

## 3. 用户与租户边界

角色包括学生、教师、作者/学科专家、机构管理员、采购决策者、平台运营者、家长/监护人（依地区政策）和受限AI代理。权限必须同时校验Tenant、主体、角色和资源归属；前端隐藏按钮不构成授权。

## 4. 核心业务对象与生命周期

- ExperimentPackage：draft→validating→review→published→deprecated/withdrawn；发布版本不可变。
- Assignment：draft→published→active→closed→archived。
- ExperimentAttempt：not_started→in_progress→submitted→assessed；撤销必须审计。
- RuntimeSession：created→ready→running↔paused→completed/failed/cancelled；合法转换由状态机定义。
- Notebook：draft→submitted_snapshot→returned/revision（依任务策略）。
- Assessment：draft→published→revised；绑定Submission和Rubric版本。
- Execution：queued→leased→running→succeeded/failed/expired/rejected；Worker不得自行修改权威Session。

## 6. 核心业务规则

1. Assignment必须引用已发布不可变Package版本。
2. ExperimentAttempt启动后锁定Package、Model、Solver和Rubric依赖。
3. Runtime状态只能由Command Handler改变。
4. 同Session权威命令按明确序列化规则处理。
5. 幂等键相同但请求哈希不同必须拒绝。
6. Worker不能直接更新Session权威状态。
7. Observation必须追溯到模型变量、执行和单位。
8. Submission提交后形成不可变快照；重交生成新版本。
9. 教师只能访问授权课程和学生数据。
10. AI工具权限不高于委托用户，并受租户、资源和动作范围约束。
11. Package撤回不得破坏历史Session审计与解释。
12. 数据删除与法定保留要求冲突时必须走批准策略，不得静默绕过。

## 7. 异常与恢复

| 场景 | 系统行为 | 恢复要求 |
|---|---|---|
| 网络中断 | 保留服务端已确认状态，本地草稿明确标记 | 重连按版本合并，不静默覆盖 |
| 命令重复 | 返回原CommandReceipt | UI展示权威状态 |
| 并发版本冲突 | 拒绝旧stateVersion写入 | 刷新状态后重试 |
| Worker超时/崩溃 | Execution失败/过期，按策略重派 | 保留输入和失败原因 |
| 旧Worker迟到 | fencing拒绝结果 | 不改变Session |
| Package撤回 | 阻止新任务按策略启动 | 历史数据仍可读 |
| 截止时间竞争 | 服务端权威时间和事务顺序裁定 | 明确返回截止结果 |
| 重复提交 | 幂等返回既有提交或明确创建新版本 | 不产生意外重复评分 |
| 权限撤销 | 后续请求重新鉴权 | 拒绝敏感缓存访问 |
| 导出失败 | 记录任务状态并安全重试 | 不暴露不完整文件 |

## 8. 非功能需求

安全：租户隔离、RBAC/ABAC、最小权限、密钥管理、输入校验、审计和依赖扫描。正确性：单位/量纲、参考算例、求解容差和模型适用域由学科专家签核。一致性：幂等、状态版本、事务Outbox和Worker fencing。可恢复性：Worker重启、消息重复、网络分区和调度器接管测试。可观测性：关联Tenant/Session/Execution的日志、指标和Trace，敏感字段脱敏。可访问性：键盘、语义标签、对比度、非颜色提示。兼容性：首期现代桌面浏览器，矩阵在试点前冻结。性能：基准测试前不编造SLO，需定义p50/p95/p99、并发、数据规模和环境。隐私：数据最小化、目的限制、保留/删除/导出及供应商审查。可维护性：契约版本化、迁移可回滚、ADR记录重大决策。

## 9. 遥测事件

至少定义experiment_opened、hypothesis_saved、session_created、command_accepted/rejected、execution_started/completed/failed、observation_recorded、notebook_saved、submission_created、assessment_published和feedback_viewed。采集遵守数据最小化；遥测不等同于学习效果。

## 10. P0验收基线

学生完成DC Circuit两组参数实验；计算、仪表、表格和图表一致；Notebook快照不可变；教师查看证据并评分；越权、重复命令、并发冲突和旧Worker结果被拒绝；Package版本可追溯；Worker失败可恢复；关键数据与事件可审计。

## 11. 待决策/待验证

首发地区、目标年级、课程标准和语言；学校/个人市场优先级；最低设备/浏览器矩阵；离线边界；真实用户研究；性能SLO与容量；数据驻留、保留期、监护人授权及跨境数据流；LTI/OneRoster Profile；科学模型专家签核与误差阈值。影响安全、科学正确性或用户数据权利的未决项均为上线阻断项。
