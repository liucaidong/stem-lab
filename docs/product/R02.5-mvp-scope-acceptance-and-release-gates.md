# R02.5 教学MVP范围、验收标准与发布门禁

- 版本：0.1；日期：2026-11-02
- 状态：基线草案；待学科专家和试点确认
- 上游：R02.1–R02.4；下游：R02.6、R03技术审计和工程验收

## 1. MVP目标

验证一个完整、科学正确、可追溯的教学实验闭环，而不是展示平台全部技术能力。唯一教学MVP为 **DC Circuit & Ohm's Law（直流电路与欧姆定律）**。RC Circuit是独立Runtime/ODE/Worker技术验证，不纳入教学内容MVP验收。

## 2. 用户和场景

- 学生：在课程任务中完成串联直流电路实验，记录预测、操作、测量、数据和结论。
- 教师：布置实验、查看进度、审阅学生证据并按Rubric评分。
- 内容作者/运营：通过受控流程校验并发布固定版本Package。
- 管理员：建立测试租户、用户和角色，验证访问隔离。

## 3. P0纳入范围

### 科学内容
- 理想直流电源、理想电阻、导线和开关；
- 简单串联电路拓扑；
- 欧姆定律和串联等效电阻；
- 电源电压、电阻值变化对电流的影响；
- 电压表、电流表；
- 至少两组参数实验和I-V数据分析。

### 学生体验
学习目标与安全/操作提示；假设/预测；元件参数调整和电路连接（首版采用受限模板）；Start/Pause/Step/Reset；仪表读数、数据表和I-V图；Notebook与提交快照；提交状态和教师反馈。

### 教师体验
创建课程/班级和成员；从固定Package版本创建Assignment；配置截止时间、尝试次数和Rubric；查看进度、提交、观测和实验记录；评分和反馈。CSV/JSON导出是否纳入P0由试点需求确认。

### 平台基础
Tenant上下文与资源级授权；Package/Model版本锁定；Runtime状态机和命令幂等；Worker隔离和结果fencing；Observation来源追溯；关键审计日志和错误恢复。

## 4. P0明确排除

并联/复杂网络、交流电路、瞬态电磁场、半导体器件、SPICE兼容、有限元、任意脚本、用户自定义服务器代码、生产Remote Lab、真实设备控制、VR/AR、复杂3D、多人协同编辑、自由插件市场、正式成绩自动生成、AI代替学生完成实验、完整LMS/SIS替代、全学科内容库和全课程标准映射。

## 5. 端到端验收场景

### E2E-01 学生完成实验
前置：学生加入课程，Assignment有效，Package已发布。
1. 学生打开任务并查看目标。
2. 输入初始预测。
3. 打开串联电路实验，设置电源和电阻。
4. 运行模型，观察电流与各电阻压降。
5. 改变一个参数，再次运行。
6. 仪表、数据表和图表展示一致结果。
7. 学生引用观测并写出结论。
8. 提交Notebook快照。
通过条件：流程完成；单位、数据来源、Package/Model版本可追溯；提交快照不可变。

### E2E-02 教师评价
教师创建Assignment并固定Package版本；学生提交；教师查看假设、操作轨迹、Observation和结论；教师按Rubric评分并反馈。
通过条件：教师仅访问授权课程；评分绑定Submission/Rubric版本；审计完整。

### E2E-03 科学正确性
对批准参考参数集运行模型，计算等效电阻、电流和元件压降，并检查KVL及适用的功率/单位关系。
通过条件：参考算例在学科专家签核容差内。容差不得由开发者任意指定。

### E2E-04 Runtime可靠性
重复相同幂等命令；提交过期stateVersion；Worker执行中崩溃并重派；旧epoch Worker迟到提交；Outbox消息重复投递。
通过条件：无重复副作用、无状态倒退、旧结果拒绝、故障可恢复。

### E2E-05 租户隔离
通过修改ID尝试访问其他Tenant的Course、Assignment、Session、Submission和Observation。
通过条件：API、后台任务、导出和对象存储访问均拒绝越权，不能只依赖前端隐藏。

### E2E-06 Package发布
执行Schema、引用、语义、安全和科学验证。
通过条件：阻断项失败不得发布；发布版本不可变；Session解析的依赖摘要可回查。

## 6. 验收指标

| 指标 | 定义 | 目标策略 |
|---|---|---|
| 实验启动成功率 | 有效启动请求中成功进入ready/running的比例 | 试点建立基线后设目标 |
| 实验完成率 | 完成提交的Attempt/有效启动Attempt | 按课程和设备分层 |
| 数据完整率 | 必填Observation字段完整比例 | 所有必填字段校验通过 |
| 结果可复现率 | 固定输入/版本在声明容差内重现的比例 | 批准参考算例验收集全部通过 |
| 命令幂等性 | 重放不产生额外状态变更 | 全部自动化用例通过 |
| 旧执行拒绝 | 过期epoch/lease结果拒绝 | 故障注入用例全部通过 |
| 教师审阅耗时 | 完成一次报告审阅的时间 | 试点采集，不预设目标 |
| 学习价值 | 概念测验和论证Rubric变化 | 使用适当测量设计，不夸大因果 |
| 单次实验成本 | 计算、存储、带宽和运营分摊 | 试点测量后设预算 |

## 7. 发布门禁

### Gate A — 产品与科学内容
学习目标、适用年级和先修要求经教师/学科专家确认；DC模型方程、单位、参考算例和误差容差签核；学生/教师关键任务可用性测试完成；P0需求有验收用例。

### Gate B — 安全与隐私
Tenant/资源授权和RLS测试通过；学生数据流、保留、删除、导出和访问控制经法律/隐私审查；日志、AI和第三方供应商数据流登记；威胁建模和高风险缺陷关闭。

### Gate C — Runtime与数据可靠性
幂等、并发冲突、事务Outbox、重复投递、Worker fencing测试通过；失败恢复和数据一致性测试通过；关键Observation和Submission可追溯。

### Gate D — 运行质量
浏览器/设备矩阵和性能基准完成；备份恢复、监控告警、支持流程和回滚方案可用；试点容量和成本预算获批。

任一Gate未通过，不得标记正式发布。受控试点须有明确风险、数据保护和参与者授权。

## 8. RC Circuit独立技术验收

选定ODE和参考解；验证固定/自适应步长策略；验证Simulation Clock与Wall/Render Clock分离；验证Worker隔离、lease、epoch fencing和结果提交；注入超时、崩溃、重复任务和调度器接管；保存误差、性能、资源占用和恢复记录。RC结果不能替代DC教学内容科学审核。

## 9. 试点阶段

阶段1：内部专家走查和自动化验收；阶段2：小规模教师/学生可用性测试；阶段3：受控课堂试点；阶段4：复盘后决定扩展学科和学校数量。每阶段定义退出条件、数据授权和风险处置。

## 10. 范围变更规则

新增P0功能必须说明其对学生/教师闭环的必要性、替代方案、科学/安全影响、工期和测试成本。不得因实现方便或竞品拥有该功能而自动纳入MVP。
