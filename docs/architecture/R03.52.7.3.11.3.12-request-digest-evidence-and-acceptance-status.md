## 2. Verified facts vs proposals

Verified from source:
- v2alpha1 does not contain request_digest or idempotency_key.
- PostgreSQL verifies Ed25519 over the encoded payload but does not independently recalculate the business request digest.
- Operation parameters are separately passed to several SQL handlers.
- Receipt key in the fixture is tenant + operation_id.
- Existing reference suite has 46 resource authorization tests and is retained in CI.

Proposals:
- v2alpha2 adds explicit contract_version, idempotency_key and SHA-256 request_digest.
- Versioned Typed Encoding is preferred over RFC 8785, conditional on PostgreSQL proof.
- Receipt identity is tenant + action + idempotency_key.
- Database recomputes digest from signed identity claims plus actual typed operation arguments.

Unverified:
- PostgreSQL 17 built-in sha256(bytea) documented; exact PG17.11 CI execution still pending.
- Exact end-to-end signer call site and key custody.
- Full action call-site inventory outside the fixture.
- PostgreSQL helper byte encoding is implemented in the disposable conformance SQL; handler-level use of the helper is not implemented.
- Atomicity under all false/null/exception paths.
- Current CI results for this branch.
