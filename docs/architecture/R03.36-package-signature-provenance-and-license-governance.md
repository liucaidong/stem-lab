# R03.36 Package Signature、Provenance 与 License Governance

- 版本：0.1；日期：2026-11-02
- 状态：CI Run #106通过结构/静态策略验证（局部）；未执行密码学验签/法律审查；DEC-27/28/29保持OPEN
- 关联：R03.8、R03.20 DEC-27/28/29、R03.30、R03.31、R03.34、R03.35

## 1. 三类证据不可互相替代

- Package Digest：识别具体内容，不证明发布者身份。
- Signature：验证某信任主体对指定Digest的密码学签署，不证明内容科学正确或许可充分。
- Provenance：描述构建者、源版本、构建过程和材料，不自动证明声明真实。
- License Evidence：记录来源、许可文本/标识、署名与权利依据；SPDX ID不是法律意见，也不单独证明再分发权。

## 2. Signature Envelope

签名信封绑定Package ID、Version、Digest Profile和Package Digest；每个签名声明key_id、signer_identity、algorithm、signature_value和signed_at。验证器必须从受控Trust Registry解析公钥/证书，不信任Package自带公钥。

生命周期状态至少包括 active、rotated/superseded、revoked、expired。密钥轮换生成新key_id，旧Key保留历史验证材料；撤销记录必须含生效时间、原因、撤销主体和审计事件。验证历史Package时需要明确“签署时有效”还是“当前仍受信任”的策略，并保留时间戳/透明日志证据。

本阶段Schema仅定义信封结构与信任注册表检查，不执行真实密码学验签。生产验签需独立Spike比较Ed25519、ECDSA P-256、RSA-PSS及KMS/HSM/Keyless身份绑定。

## 3. Provenance Attestation

Predicate记录builder_id、build_type、source repository/revision、materials资源Digest、build_started_at和build_finished_at。Package subject必须与R03.35的(package_id, version, digest_profile, digest)完全匹配。材料列表必须可映射到R03.34 Dependency Closure；当前Fixture验证基本结构，不实现CI可信构建证明或远程Attestation服务。

候选封装：DSSE/in-toto/Sigstore或受控KMS。需比较主体身份、签名消息编码、证书链、OIDC issuer/audience、透明日志、密钥撤销和离线验证。

## 4. License Governance

每个可分发Asset必须有独立License Record，绑定asset_id和asset_digest，包含license_expression、source origin、author/supplier、copyright、modified状态、commercial_use、redistribution、modification、attribution、evidence_ref和review。

Policy默认拒绝未知许可：
- allowlist：经法律/内容治理批准的SPDX License ID；
- denylist：禁止使用/再分发的许可或兼容性冲突；
- exception：必须限定Asset、用途、客户/地域、审批人和到期时间；
- pending/rejected审核不得发布；
- commercial_use和redistribution必须分别核实，不能由license_id自动推断。

SPDX License Expression应按官方语法解析；本阶段仅以受控License ID allowlist/denylist做策略样例，不声称完整SPDX解析或法律兼容性验证。License文本、第三方合同和个人信息放在受控Evidence Store，Manifest只保存稳定证据引用。

## 5. 发布门禁

Release Gate要求：
1. Canonical Digest profile已批准且Digest可重算；
2. 至少一个有效签名绑定完全相同的Package subject；
3. 签名Key在适用时间策略下有效、未撤销；
4. Provenance source、builder和materials与发布流水线/依赖闭包匹配；
5. 所有Asset有匹配Digest的License Record；
6. License审核状态approved，权利范围覆盖目标商用/分发场景；
7. 未知、denylist、过期例外或缺少证据一律BLOCK RELEASE；
8. 发布决策、豁免、验证报告和撤销事件可审计。
