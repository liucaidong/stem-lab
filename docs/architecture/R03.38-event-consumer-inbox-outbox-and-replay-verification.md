# R03.38 Event Consumer、Inbox、Outbox 与 Replay 可执行验证

- 版本：0.1；日期：2026-11-02
- 状态：SQLite持久化集成测试Harness草案；非PostgreSQL/NATS生产集成
- 关联：R03.7、R03.10、R03.20 DEC-05/DEC-30、R03.32、R03.37

## 1. 验证边界

本阶段把R03.32测试计划转化为可执行的SQLite-backed集成测试Harness。它使用真实SQLite文件、事务、唯一约束、Inbox/Outbox表、Broker消息模拟表、Consumer Cursor、DLQ和副作用表，执行崩溃窗口和重复投递测试。

它不是NATS JetStream、PostgreSQL、生产Worker或分布式部署集成测试。SQLite模拟Broker接受/ACK状态，不能证明真实Broker网络、持久化、分区、重平衡或故障语义。

## 2. 事务不变量

Producer事务原子写入Aggregate State与Outbox；事务失败时两者都回滚。Relay先向Broker模拟表写入，再标记Outbox已发布；在Broker接受后、Outbox标记前崩溃会造成重复投递，这是At-Least-Once允许的窗口。

Consumer事务先验证Tenant、Inbox去重、Sequence Guard，再写Projection/Side Effect/Inbox/Cursor并提交；Broker ACK发生在事务提交之后。提交后ACK前崩溃时，重投由Inbox唯一键去重，不重复副作用。

## 3. 顺序和幂等规则

- event_id + consumer_id是Inbox唯一键；
- 同event_id同digest为重复投递，Ack但不重复副作用；
- 同event_id不同digest为完整性冲突，拒绝；
- sequence > cursor+1视为gap，不推进cursor、不Ack，等待缺失事件；
- sequence <= cursor不允许回滚Projection；
- 每个aggregate独立维护sequence；
- Tenant必须来自可信订阅/Consumer上下文，跨Tenant消息拒绝；
- Poison Event有界重试，达到阈值进入DLQ并按策略Ack原消息。

## 4. 可执行测试

脚本：scripts/test_event_delivery_sqlite.py

当前10项测试：
1. Producer Aggregate State与Outbox原子回滚；
2. Relay在Broker接受后崩溃导致重复投递，Consumer只产生一次副作用；
3. 重复事件幂等；
4. 同event_id不同Digest拒绝；
5. Sequence Gap等待缺失事件并恢复；
6. Consumer提交后ACK前崩溃，重投不重复副作用；
7. Replay重复事件去重；
8. Poison Event有界重试与DLQ；
9. 跨Tenant投递拒绝；
10. Consumer事务失败不写ACK。

## 5. 证据与非目标

CI通过只证明SQLite Harness测试通过。NOT TESTED：
- PostgreSQL事务隔离、RLS、并发锁与真实Inbox/Outbox DDL；
- NATS JetStream持久化、AckWait、redelivery、consumer group、stream retention和DLQ；
- 多进程/多主机竞态、网络分区、Broker故障；
- 外部副作用系统的幂等键和回滚；
- 生产Worker lease/fencing与Event sequence原子提交；
- 大规模吞吐、延迟、保留和重放成本。

DEC-05（NATS）与DEC-30（Delivery semantics）仍需基于真实Spike决策；测试Harness不自动关闭任何基础设施选型。
