# R03.40 API Security 与 Operational Semantics

- 版本：0.1；日期：2026-11-02
- 状态：API安全/操作语义契约草案；未实现生产API Middleware
- 关联：R03.10、R03.20 DEC-20–26、R03.28、R03.37、R03.39

## 1. JWT Issuer / Audience / Claims

访问令牌必须验证签名、允许算法、Issuer精确匹配、Audience包含本API、exp/nbf/iat时间边界、sub存在、JWKS来源和密钥轮换。Tenant/Actor身份不能由请求Body覆盖；Tenant Membership和资源角色需从可信服务端数据解析。JWT claim校验不等于资源级授权。

## 2. Resource-Level Authorization

每次请求执行Tenant边界、资源存在性、角色/关系、操作能力、数据分类和状态约束。默认拒绝；资源ID不可作为授权证明。跨租户资源应避免泄露存在性。后台服务身份需明确任务范围与审计上下文。

## 3. Idempotency-Key

建议作用域：(tenant_id, actor_id, operation_id, idempotency_key)。记录request_hash、状态、原始Response/Receipt、created_at和expires_at。相同Key+相同Hash返回原始结果；相同Key+不同Hash返回409 IDEMPOTENCY_KEY_CONFLICT；并发相同Key必须只有一个执行者。保留期和canonical request hashing算法仍待ADR决策。

## 4. Cursor Pagination

Cursor必须绑定tenant、resource/query filter、稳定排序键（含唯一tie-breaker）、snapshot watermark、版本和过期时间；签名/HMAC防篡改，拒绝跨Tenant/跨Filter复用。不得只编码offset。Cursor过期返回稳定错误码并要求客户端重新分页。Cursor签名密钥需轮换、版本化和常量时间比较。

本阶段用合成HMAC测试验证篡改/过期/tenant/filter绑定；真实密钥管理和跨版本Cursor迁移未测试。

## 5. Rate Limit / Retry-After

Rate Limit按Tenant、Actor、Endpoint和资源成本分层；429响应携带Retry-After秒数或HTTP日期，客户端使用有抖动的指数退避。Rate limit key、窗口算法和配额公平性需压测决定。服务端错误不得无限重试。

## 6. Error Taxonomy

稳定Error Code与HTTP状态映射；包含retryable、Retry-After适用性、field_errors和correlation_id。错误Message不得泄露SQL、密钥、租户存在性或内部堆栈。新增错误码只追加；改变语义需版本/兼容评审。

## 7. Command Payload Schema Registry

Command以command_type + schema_version寻址到Payload Schema；每项登记允许Actor、幂等要求、expected stateVersion、timeout、cancellation和副作用类别。未知命令/版本拒绝。命令Payload不能携带tenant_id/actor_id作为可信授权来源。
