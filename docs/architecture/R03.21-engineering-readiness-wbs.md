# R03.21 技术验证与工程准入工作分解（WBS）

- 版本：0.1；日期：2026-11-02
- 状态：执行计划；所有未执行项为NOT STARTED
- 关联：R03.18、R03.19、R03.20

## 1. 状态规则

NOT STARTED、IN PROGRESS、BLOCKED、PASS、FAIL。PASS必须附证据链接、Git commit、环境、执行者和审阅者。任务卡、代码文件或CI配置存在不等于PASS。

## 2. Work Breakdown Structure

### W0 治理与基线
- W0.1 确认首发市场、年级、课程标准和试点边界；
- W0.2 确认产品需求负责人、科学负责人、安全/隐私负责人；
- W0.3 为所有待决策项分配负责人和决策日期；
- W0.4 建立需求、ADR、Schema和测试的追踪关系。

退出条件：关键产品决策有书面结论；未决项有负责人和期限。

### W1 科学模型验证
- W1.1 定义DC串联电路受限拓扑和变量；
- W1.2 由学科专家签核欧姆定律、KVL和仪器语义；
- W1.3 建立DC参考输入/输出算例；
- W1.4 建立RC ODE解析/高精度参考解；
- W1.5 选定单位/量纲方案并建立测试集。

退出条件：模型契约、算例、容差和专家签核归档。

### W2 Contract First
- W2.1 冻结Package JSON Schema；
- W2.2 冻结Model Contract和Observation Schema；
- W2.3 冻结Runtime Command/State/Event契约；
- W2.4 冻结Learning数据对象和ERD；
- W2.5 生成OpenAPI和事件Schema；
- W2.6 建立正/负样例和兼容性测试。

退出条件：Schema通过CI验证，所有契约有版本和变更策略。

### W3 基础设施Spike
- W3.1 PostgreSQL事务、迁移、RLS和连接池；
- W3.2 Outbox与NATS重复/乱序/重放；
- W3.3 Python Worker协议、超时和取消；
- W3.4 Lease/Epoch/Fencing和Scheduler接管；
- W3.5 Object Storage上传、digest、权限和孤儿清理；
- W3.6 OTel全链路关联。

退出条件：故障注入报告通过，阻断缺陷关闭。

### W4 产品原型验证
- W4.1 学生DC实验Workspace低保真/高保真原型；
- W4.2 教师Assignment与审阅原型；
- W4.3 学生/教师可用性测试；
- W4.4 键盘、语义和屏幕阅读器检查；
- W4.5 目标设备渲染性能验证。

退出条件：关键任务完成率、问题清单和修订记录经评审。

### W5 安全与隐私
- W5.1 数据目录和数据流图；
- W5.2 目标法域隐私/未成年人评估；
- W5.3 Threat Model和滥用案例；
- W5.4 RLS/API/对象存储/Worker安全测试；
- W5.5 AI工具威胁测试（AI进入范围前）。

退出条件：高风险缺陷关闭，法律和安全负责人签核。

### W6 工程准入复审
- W6.1 汇总W1–W5证据；
- W6.2 更新R03.19阻断项状态；
- W6.3 召开产品/科学/架构/安全评审；
- W6.4 形成是否申请解除代码冻结的建议；
- W6.5 用户明确批准后才解除冻结。

退出条件：所有适用Gate通过；不得以计划完成替代实际证据。

## 3. 依赖关系

W0决定产品/合规边界；W1和W2可部分并行，但正式Model Schema依赖单位/学科输入；W3依赖W2关键协议；W4可先做原型但最终验证依赖稳定的学生流程；W5从设计阶段持续进行；W6依赖所有阻断证据。

## 4. 风险优先级

最高优先级：科学模型错误、跨租户数据泄露、Runtime状态倒退/重复副作用、Worker旧结果覆盖、Package任意代码执行、未成年人数据违规。性能和成本虽重要，但不得以牺牲上述正确性/安全性换取。
