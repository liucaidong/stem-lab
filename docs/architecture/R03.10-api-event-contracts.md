# R03.10 HTTP API、事件信封与契约版本策略

- 版本：0.1；日期：2026-11-02
- 状态：API契约草案；OpenAPI/AsyncAPI需后续生成和验证
- 关联：R02.3 FR-RT/FR-LRN、R03.6 TF-02/09

## 1. 契约原则

首期HTTP API候选为REST/JSON，OpenAPI作为请求/响应契约源。事件契约独立版本化。API不暴露数据库结构；tenant_id和actor_id从可信认证上下文派生，不接受客户端自报。错误码稳定、可机器处理；响应携带correlation_id。

## 2. API资源边界

候选资源：
- /v1/courses、/v1/classes、/v1/assignments；
- /v1/experiment-packages、/v1/package-versions；
- /v1/experiment-instances；
- /v1/sessions、/v1/sessions/{id}/commands；
- /v1/sessions/{id}/events、/observations；
- /v1/notebooks、/v1/submissions；
- /v1/submissions/{id}/assessments；
- /v1/tenants、/v1/integrations（受管理员权限保护）。

资源和操作必须按领域职责划分，禁止为方便前端而提供可绕过Command Handler的Runtime直接写接口。

## 3. 写请求语义

所有非幂等写操作需Idempotency-Key；Runtime命令同时需expected_state_version或If-Match。请求体包含schema_version和领域payload，不包含可信actor/tenant身份声明。

同Key同请求哈希返回原结果；同Key不同Hash返回冲突。并发版本不匹配返回409并提供当前ETag/stateVersion。服务端验证时间和截止时间，不信任客户端时钟。

时间戳使用RFC3339 UTC；科学时间使用独立数值字段和单位。分页使用cursor，不依赖可变offset。排序必须稳定并包含唯一tie-breaker。

## 4. API错误模型

统一错误结构建议：
- code：稳定机器码；
- message：可读描述，不包含敏感内部信息；
- correlation_id；
- retryable；
- field_errors（可选）；
- current_version（并发冲突时可选）。

错误分类：400输入/Schema错误；401未认证；403无权限；404资源不存在或按策略隐藏；409状态/幂等/版本冲突；422科学/业务约束失败；429配额/限流；5xx服务端故障。具体HTTP映射在OpenAPI冻结。

## 5. Runtime命令API草案

POST /v1/sessions/{id}/commands
- Header: Idempotency-Key、If-Match（或expected_state_version）、Authorization；
- Body: command_type、schema_version、payload、client_command_id（可选）；
- Response: command_receipt_id、accepted/rejected、resulting_state_version、session_status、correlation_id。

该接口只接受受Package声明的命令和参数。Start/Pause/Resume/Step/Reset/Cancel/SetParameter分别定义Schema、前置状态、权限和副作用。

GET /v1/sessions/{id}返回权威状态和版本；GET events使用稳定cursor；GET observations返回分页数据或Dataset引用。大文件导出使用短期授权URL，权限校验发生在签发时和必要的下载代理层。

## 6. 事件信封

每条事件包含：
- event_id；
- event_type；
- schema_version；
- tenant_id；
- aggregate_type、aggregate_id；
- aggregate_sequence；
- state_version（适用时）；
- epoch（执行相关时）；
- occurred_at；
- correlation_id、causation_id；
- payload。

事件只表示已提交事实。Outbox在业务事务中写入；Publisher异步投递；Consumer必须幂等。消息至少一次投递，不能假定恰好一次。NATS JetStream去重是优化，不替代业务幂等和顺序校验。

## 7. 事件类型候选

SessionCreated、SessionReady、CommandAccepted、CommandRejected、SessionStarted、SessionPaused、SessionResumed、ExecutionQueued、ExecutionLeased、ExecutionStarted、ExecutionSucceeded、ExecutionFailed、ObservationRecorded、SessionReset、SessionCompleted、SessionCancelled、SubmissionCreated、AssessmentPublished、PackageReleased、PackageWithdrawn。

事件名称和粒度需与领域事件区分；不得把每个内部日志都发布成公共领域事件。

## 8. 顺序、重放与Schema演进

aggregate_sequence在单一聚合内单调递增；消费者发现序号缺口时暂停应用并按策略补拉/重放。事件处理记录event_id和聚合序号。重放必须隔离副作用：不能重复发送邮件、重复评分或再次启动Worker。

向后兼容字段新增优先可选；删除/改名/语义变化需新Schema版本和迁移窗口。消费者必须明确支持的版本范围；未知破坏性版本安全失败并告警。事件保留和重放窗口由成本与恢复目标确定。

## 9. OpenAPI/Contract Test

每个API操作定义认证、权限、请求Schema、响应Schema、错误、幂等、版本和限流。Contract Test覆盖成功/失败、未知字段策略、版本冲突、幂等重放、越权和分页稳定性。事件Consumer Contract Test覆盖重复、乱序、缺口、重放、未知版本和故障恢复。
