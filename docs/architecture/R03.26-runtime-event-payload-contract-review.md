## 2. 事件语义

### SessionStarted

记录新Execution启动时所需的不可变关联信息：execution_id、input_state_version、epoch、fencing_token、solver_id/version和package_digest。消费者可据此关联输入快照与执行租约；不能仅凭事件Payload授予Worker写权限。

### ExecutionSucceeded

记录执行输出摘要、Solver版本、resulting_state_version、simulation_time和observation_count。该事件只在结果已通过服务端校验并提交后发布；不能把Worker本地“计算完成”当作已提交事实。

### ObservationRecorded

记录Observation标识、quantity、单位、仿真时间、来源类型及标量值/数据引用。大数据使用value_ref；不得把大体积数组直接嵌入事件Payload。

## 3. 校验链路

1. 通用Envelope Schema验证事件信封字段；
2. Registry按event_type和schema_version解析Payload Schema；
3. 对Payload执行对应Draft 2020-12 Schema验证；
4. Consumer继续验证aggregate_sequence、event_id幂等、tenant归属和副作用边界。

仓库验证脚本已扩展为读取Registry、检查event_type/schema_version唯一性、验证三种事件Envelope/Payload Fixture，并对每种Payload执行负向断言（缺少必需字段、digest格式错误、value/value_ref冲突）；该版本脚本尚未取得GitHub Actions成功运行证据。

## 4. 已知缺口

- 当前仅覆盖三种代表事件；SessionCreated/Ready/Paused/Resumed/Reset/Cancelled、CommandAccepted/Rejected、ExecutionQueued/Leased/Started/Failed、PackageReleased/Withdrawn、Submission/Assessment等候选事件尚未形成Payload Schema。
- Registry尚未定义每个事件的producer权限、consumer订阅者、保留期、重放策略和敏感数据分类。
- Schema无法验证事件是否对应已提交事实、aggregate_sequence是否连续、事件是否重复或跨租户引用。
- output_digest/package_digest格式检查不等于字节级摘要验证。
- 事件兼容性测试、消费者幂等测试、乱序/缺口/重放故障注入尚未执行。

## 5. 当前结论

W2.3继续IN PROGRESS。通用Envelope之上已建立三种代表事件的Payload Schema和Fixture，并将Registry验证纳入脚本；尚未实现完整事件目录、正式CI运行、Consumer Contract Test或消息系统Spike。事件契约未冻结。
