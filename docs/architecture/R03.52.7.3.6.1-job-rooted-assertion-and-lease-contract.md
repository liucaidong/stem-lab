# R03.52.7.3.6.1 — Job-Rooted Assertion and Lease Contract v2alpha1

- Status: experimental reference contract; **PROPOSAL / NOT APPROVED FOR PRODUCTION**
- Branch: `r03-52-7-3-6-resource-scoped-auth-reference`
- Product Code Freeze: ACTIVE
- P3.17: OUT OF SCOPE
- R03.44: CONDITIONAL_NOT_READY; `production_ready=false`
- Compatibility: v1alpha1 remains unchanged

## 1. Purpose

Introduce a separately versioned, closed assertion-claims schema and JobLease schema that can express the Job→Session relationship missing from v1alpha1. This increment is deliberately contract-only. It does not implement cryptographic signing, PostgreSQL verification, RLS, nonce persistence, Store operations, or a production adapter.

## 2. Candidate v2alpha1 assertion claims

The schema binds:

- issuer and key identity: `iss`, `kid`;
- principal and tenant: `sub`, `tenant_id`;
- relying party and operation class: `aud`, `action`;
- resource root and persisted relationship: `job_id`, `session_id`;
- lease fencing: `owner`, `epoch`;
- operation correlation: `operation_id`;
- validity and replay key: `iat`, `exp`, `nonce`.

Unknown claims are rejected. The action vocabulary is intentionally finite:
`worker.job.renew`, `worker.job.complete`, `worker.job.fail`,
`worker.job.retry`, `worker.job.dead_letter`, `worker.dlq.replay`,
`worker.outbox.dispatch`, and `worker.receipt.reconcile`.

This is a candidate vocabulary for reference testing, not an approved authorization policy. Claim/lease issuance and the exact semantics of dispatcher and replay capabilities remain subject to security/product review.

## 3. Candidate v2alpha1 JobLease

The new lease adds `session_id`; v1alpha1 is not mutated. The lease object is consistency/context data only. It is not itself a credential. The signed assertion plus persisted database Job→Session relationship and current owner/epoch/state/DB-clock expiry are the authority.

## 4. Cross-field semantics

JSON Schema checks shape and closed fields. The reference semantic test additionally checks `exp > iat` and a maximum lifetime of 120 seconds as a test-profile parameter. That value is not a production TTL decision. The PostgreSQL verifier must independently enforce equivalent time bounds using database time.

## 5. Explicit non-goals

- No production key custody, issuer service, rotation/revocation operations, or signing API.
- No claim that the test action vocabulary is approved.
- No production nonce retention duration.
- No PostgreSQL RLS or SECURITY DEFINER verifier.
- No proof of one-transaction nonce consumption.
- No change to DEC-03, DEC-14, or R03.44 readiness.
- No production Store Adapter.

## 6. Acceptance criteria for this increment

1. v1alpha1 files remain byte-for-byte unchanged.
2. Both v2alpha1 schemas pass Draft 2020-12 meta-schema validation.
3. Unknown claims and missing/invalid Job, Session, Owner, Epoch, Operation, action, and nonce fields fail closed.
4. Semantic expiry ordering and maximum-lifetime test cases are covered.
5. CI runs the new contract test.
6. Results are reported as schema/semantic validation only, not database security evidence.
