# R03.49 Package Ingestion State Machine & Quarantine Lifecycle Contract

- Version: 0.1
- Date: 2026-11-02
- Status: Lifecycle schema and semantic validator; CI pending
- Parent: R03.48
- Risks: AUD-001, AUD-002
- Product Code Freeze: ACTIVE

## 1. Objective

Define a durable, auditable lifecycle for Package ingestion without conflating byte validation with trust approval or publication. The lifecycle is a contract and state-transition harness, not a production ingestion service.

## 2. State model

| State | Meaning |
|---|---|
| created | Ingestion session allocated; no bytes accepted yet |
| receiving | Bounded upload stream is in progress |
| received | Upload completed; immutable archive digest/size recorded |
| quarantined | Bytes are isolated pending validation |
| validating | Validation worker holds a fenced validation attempt |
| validated | Structural, archive and configured byte-integrity checks passed |
| rejected | Terminal validation/policy rejection |
| revoked | Previously validated package/session is no longer trusted/usable |
| expired | Session TTL elapsed before validation completed |

Validated does not mean signed, licensed, approved for publication or production-ready. Those are independent trust gates and remain governed by DEC-28/29.

## 3. Allowed transitions

- null → created
- created → receiving | rejected | expired
- receiving → received | rejected | expired
- received → quarantined | rejected | expired
- quarantined → validating | rejected | expired
- validating → validated | rejected | quarantined
- validated → revoked
- rejected/revoked/expired are terminal

A transient validation failure may return validating → quarantined with an explicit retryable reason and incremented attempt count. No transition may skip quarantine or validation.

## 4. Concurrency and idempotency

Each transition is an optimistic-concurrency command:
- caller supplies expected_revision;
- successful transition increments revision by exactly one;
- sequence is monotonic and from_state must equal the prior resulting state;
- command_id is unique;
- idempotency scope is tenant + session + operation + key;
- same idempotency key + same request digest returns the original receipt and does not append another transition;
- same key + different request digest returns IDEMPOTENCY_KEY_CONFLICT.

The validator models this contract but does not implement a distributed idempotency store or database transaction.

## 5. Validation evidence gate

Transition to validated requires:
- exact source Manifest byte digest;
- pinned Catalog Snapshot digest;
- archive byte digest;
- declared resource count;
- verified resource count equal to declared count.

This is an integrity gate only. Signature verification, signer trust, provenance approval, SPDX/license policy and malware scanning are not silently inferred from these fields.

## 6. Audit record

Every transition records sequence, from/to state, command ID, idempotency key, request digest, actor, timestamp, expected/resulting revision and optional reason code. Transition history is append-only. Timestamps are audit metadata, not Package Digest input.

## 8. Not implemented

No upload API, object storage, quarantine bucket, queue, worker lease, malware scanner, signed receipt, database persistence, cross-tenant database isolation or production lifecycle service is implemented. The state machine is not wired to Runtime Event Registry/Broker.

## 9. Exit criteria

R03.49 fixture scope passes when schema and state-transition semantics, optimistic revision, append-only sequence, terminal states, evidence gate and idempotency outcomes all pass CI. This does not close AUD-001/AUD-002 or authorize production package publishing.
