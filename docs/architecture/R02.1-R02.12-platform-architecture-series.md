# R02.1–R02.12 平台架构设计系列（汇总基线）

- 版本：1.0；日期：2026-11-02
- 状态：架构设计基线；需通过契约评审和技术Spike后冻结
- 说明：本文件恢复并整合历史R02.1–R02.12主题。它不是此前会话逐篇原稿的逐字复原，而是基于已恢复决策重新形成的可审阅版本。

## R02.1 System Architecture — 系统总体架构

### 目标
以稳定领域边界连接实验内容、科学模型、Runtime、Renderer、学习系统、数据、AI和扩展生态。

### 逻辑分层
1. Experience：Student、Teacher、Author、Admin工作台。
2. Application：课程、作业、Catalog、Session、Notebook、Assessment用例。
3. Domain：Experiment Package、Scientific Model、Runtime、Observation、Learning Record。
4. Execution：Scheduler、Worker、Solver、Device Adapter。
5. Infrastructure：PostgreSQL、NATS、Object Storage、Cache、Observability。
6. Integration：LTI、OneRoster、OIDC/SAML、第三方工具和设备。

### 决策
首期采用Modular Monolith + Independent Scientific Worker。服务拆分由真实扩展压力驱动，不预先微服务化。

## R02.2 Scientific Model Engine — 科学模型引擎

### 职责
- Model Definition、Model Version、Model Artifact；
- 参数、状态变量、代数变量、方程、约束、初始条件；
- 单位与量纲检查；
- 输入/输出端口和模型适用范围；
- 编译/规范化、静态检查、参考算例验证；
- Solver capability要求声明。

### 不负责
Session生命周期、调度、Renderer、课程和教学流程。

### 模型契约最小组成
model_id、version、domain、variables、parameters、equations、constraints、initial_conditions、units、inputs、outputs、validity_domain、solver_requirements、validation_cases。

### 验收
同一模型版本有Schema、单位检查、参考算例、数值容差、失败案例和兼容策略。

## R02.3 Simulation Runtime — 仿真运行时

### 职责
Session创建与状态机、命令处理、状态版本、事件、Simulation Clock、Execution、暂停/恢复/重置、Snapshot/Replay和结果提交。

### 状态不变量
- 状态只通过Command Handler改变；
- 同Session命令有序；
- Command Receipt、State、Event、Outbox在一个DB事务内；
- Solver执行在事务外；
- 结果提交匹配stateVersion、epoch、execution_id和lease；
- 未验证结果不能推进Simulation Clock。

### 核心对象
RuntimeSession、RuntimeState、RuntimeCommand、CommandReceipt、RuntimeEvent、Execution、WorkerLease、Snapshot。

## R02.4 Experiment Package — 实验包体系

### 职责
以声明式Package组织学习目标、模型引用、场景、仪器、流程、评价和资源。

### 核心要求
- Package发布版本不可变；
- 子资源独立版本化；
- 发布时锁定依赖版本/digest；
- 经过Syntax、Schema、Reference、Semantic、Safety、Runtime Preflight和Scientific Validation；
- Package不得执行任意不受控服务器代码；
- Session记录完整解析依赖清单。

### 包内主要资源
Manifest、Learning Objectives、Model Reference、Scene、Instruments、Workflow、Assessment/Rubric、Assets、Locales、Validation Cases。

## R02.5 Rendering Architecture — 渲染架构

### 职责
2D/3D场景呈现、用户交互、仪器界面、图表、动画、无障碍和设备适配。

### 分层
- Scene Graph：对象、层级、资源和变换；
- Renderer Adapter：Canvas/WebGL/WebGPU等候选后端；
- Interaction Layer：选中、拖拽、连接、参数控制；
- Visualization Mapping：科学量到颜色、位置、长度、图表等视觉通道；
- Instrument UI：仪表读数与采样；
- Accessibility：键盘、语义、对比度和替代表达。

### 硬约束
Renderer不是科学计算引擎，不维护权威模型状态；动画帧率与Simulation Clock分离。具体渲染后端需通过设备覆盖和性能Spike决定。

## R02.6 Experiment Authoring System — 实验创作系统

### 作者工作流
草稿创建→学习目标→Model/Scene/Instrument绑定→Workflow设计→Rubric配置→Schema/语义校验→Sandbox预览→审核→发布不可变版本→版本迭代。

### 编辑器能力
- Package Manifest编辑；
- 模型参数和端口配置；
- 场景布局与对象绑定；
- 仪器配置；
- 实验步骤与分支；
- 数据采集和图表配置；
- 评价量规；
- 本地化和无障碍元数据。

### 安全
草稿Sandbox与生产Runtime隔离；作者内容不得直接获得生产凭证；外部资产扫描和许可元数据检查是发布门槛。

## R02.7 Scientific Data Platform — 科学数据平台

### 数据对象
Observation、ObservationSeries、Measurement、DerivedValue、Dataset、FileAsset、Analysis、Snapshot。

### 数据语义
每个科学数值必须明确quantity_id、value、unit、simulation_time或observed_at、source、model_version、execution_id、quality/status和uncertainty（适用时）。

### 存储分工
PostgreSQL保存元数据、索引和事务性状态；Object Storage保存大体积数组、波形、图像和文件；NATS只传事件，不作为唯一事实源。

### 分析能力
表格、曲线、散点、统计摘要、数据筛选、单位转换、导出CSV/JSON。所有派生数据记录计算方法和输入引用。

## R02.8 Learning & Assessment — 学习与评价系统

### 学习对象
Course、Class、Enrollment、Assignment、ExperimentAttempt、LabNotebook、Submission、Rubric、Assessment、Feedback。

### 评价维度
- 科学概念理解；
- 实验设计与变量控制；
- 仪器使用与测量；
- 数据处理和图表解释；
- 证据与论证；
- 安全与规范。

### 原则
结果评分与过程评价分开；自动评分给出可解释证据；教师保留复核/覆盖权限并留下审计记录。学习记录绑定Package、Model、Rubric版本。

## R02.9 AI Agent System — AI Agent系统

### 角色
实验助教、数据分析助手、教师备课助手、作者校验助手。Agent不是任意执行器，也不是权威科学状态持有者。

### Tool Gateway
统一工具注册、JSON Schema参数验证、scope/tenant/resource授权、审批策略、速率限制、审计、超时和撤销。

### 允许工具示例
ReadExperimentState、ReadObservations、SetAllowedParameter、Start/Pause/Step、GenerateChart、DraftConclusion、SubmitForReview（用户确认）。

### 禁止
直接数据库访问、任意Shell/Python、绕过模型约束、读取其他学生数据、无安全联锁控制真实设备。

### 可追溯
保存agent/version、tool/version、输入摘要、审批、输出、关联Session和correlation_id。

## R02.10 Plugin Architecture — 插件架构

### 插件类别
Solver Adapter、Renderer Adapter、Instrument Adapter、Content Package、Data Connector、LMS Integration、Device Adapter。

### Manifest
plugin_id、version、api_compatibility、capabilities、permissions、resource_limits、network_policy、signature、publisher、license。

### 生命周期
提交→静态检查→签名/来源验证→沙箱测试→审核→发布→安装/启用→监控→撤销/升级。

### 安全
默认不信任；最小权限；隔离执行；禁止任意访问数据库和Secrets；兼容性与供应链风险可追踪。首期不开放任意第三方代码插件市场。

## R02.11 Infrastructure Architecture — 基础设施架构

### 开发/测试基础
Docker Compose候选：API、PostgreSQL、NATS JetStream、S3兼容对象存储、Scheduler、Worker、OTel Collector。

### 生产基础
无状态API副本；Scheduler通过Lease竞争；Worker按Solver能力/队列扩展；PostgreSQL高可用与PITR；NATS持久化；Object Storage版本化；集中式Secrets和Observability。

### 运维控制
迁移管理、备份恢复、容量规划、配额、限流、故障注入、SLO、告警、事故响应、SBOM和依赖扫描。

### 不变量
Cache不是事实源；NATS不是唯一事实源；Object Storage内容通过digest校验；备份必须演练恢复。

## R02.12 MVP Engineering Blueprint — MVP工程蓝图

### 教学MVP
DC Circuit & Ohm's Law：电源、电阻、导线、开关、电压表、电流表、串联电路、欧姆定律、Observation、I-V图、实验笔记、结论和教师评价。

### 技术验证
RC Circuit：ODE求解、固定/可变步长、Simulation Clock、Worker、Scheduler、epoch fencing、结果验证和失败恢复。

### 交付阶段
- P0 Foundation：Monorepo、契约、DB、消息、对象存储、CI、可观测性；
- P1 Experiment Package：Manifest/Model/Scene/Instrument/Workflow Schema、Loader、Validator；
- P2 Scientific Model Engine：模型定义、单位、方程、Solver接口和参考算例；
- P3 Simulation Runtime：Session、Command、Event、Clock、Scheduler、Worker、Result Commit；
- 后续阶段：Rendering、Authoring、Data、Learning、AI、Plugin、Integration、Remote Lab按独立阶段推进。

### 退出条件
每阶段都有Schema/API契约、测试、可观测性、安全审查、运行手册和可回滚迁移。设计文档不能替代实现验收。

## 3. 跨模块契约

1. Package引用Model/Scene/Instrument/Workflow/Rubric的不可变版本。
2. Runtime加载已验证Package和Model Artifact。
3. Solver只接收明确版本、输入快照和执行策略。
4. Observation由Runtime/Data模块接收并保存，Renderer只读。
5. Learning Submission引用过程证据快照。
6. AI通过Tool Gateway调用Application API。
7. Plugin通过版本化Adapter Contract接入。
8. 所有跨模块事件带tenant、aggregate、sequence、schema_version和correlation_id。

## 4. 架构风险

- 科学模型语义与单位系统不统一；
- 事件Schema演进导致Replay兼容性问题；
- Worker计算结果和Session状态发生竞态；
- RLS与连接池tenant上下文泄漏；
- 大型时间序列导致数据库膨胀；
- 插件/Package供应链和恶意内容风险；
- 未成年人学习数据治理与跨境风险；
- 多Solver的确定性和数值容差定义不一致。

## 5. 冻结前必须完成

- 正式Model Schema和单位系统；
- Experiment Package JSON Schema及兼容策略；
- Runtime状态机/命令/事件契约；
- Worker协议和Result Validation；
- PostgreSQL RLS集成测试；
- NATS Outbox幂等与故障测试；
- DC Circuit参考算例与科学专家签核；
- RC Circuit数值基准；
- 学生数据治理与威胁模型；
- 生产容量与成本评估。
