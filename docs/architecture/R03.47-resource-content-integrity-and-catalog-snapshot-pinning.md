## 1. Objective

Establish verifiable byte-level integrity inputs for Package publication:
1. verify exact source Manifest bytes against the supplied source digest;
2. verify embedded resource bytes against declared size and SHA-256;
3. pin a Resource Catalog Snapshot with a deterministic snapshot digest;
4. prove catalog/dependency ordering does not change the snapshot digest;
5. keep local fixture verification separate from production ingestion, network resolution, signing and licensing.

## 2. Versioned catalog snapshot

R03.47 adds package-resource-catalog-snapshot schema v1alpha2. It adds:
- snapshot_digest: SHA-256 of the explicit catalog snapshot projection;
- snapshot_digest_profile: rfc8785-jcs-candidate-v1.

The digest projection includes catalog_version, snapshot_id, policy and all resource records. It excludes snapshot_digest itself. Resource records are ordered by resource_type/resource_id/version/digest; dependency edges are ordered by dependency identity and relation; external host allowlist is sorted.

Digest framing:

SHA-256(UTF8("stemlab-catalog-snapshot") || 0x00 || ASCII(profile-id) || 0x00 || JCS(snapshot-projection))

This is a candidate profile for immutable snapshot pinning only. It is not a decision that Package Digest must use JCS. DEC-27 remains OPEN.

## 3. Source Manifest integrity

The source Manifest digest is computed over the exact supplied UTF-8 bytes, not a parsed-and-reserialized object. The verifier:
- decodes a fixture-provided byte sequence;
- checks byte length;
- computes SHA-256;
- parses JSON with duplicate-key and non-standard-number rejection;
- checks the parsed Package ID and Version against the declared identity.

A source digest supplied by a caller is not trusted until compared to the actual bytes. R03.45's projection function still accepts a digest parameter; production callers must use a verified ingestion boundary.

## 4. Resource byte integrity

The fixture harness validates:
- strict Base64 decoding;
- exact byte length;
- SHA-256 equality;
- unique resource identity and canonical path;
- POSIX relative path, no traversal, no backslash, NFC requirement.

The current fixture covers two embedded byte payloads (JSON model and SVG asset). It does not fetch external URLs or access restricted resources.

## 5. Security boundaries

- No network fetch, DNS lookup, archive extraction or filesystem traversal is performed.
- No object storage, quarantine bucket, malware scanner or content-type sniffing is integrated.
- No symlink/hardlink race or archive bomb protection is tested.
- External and restricted resources remain metadata-only; the harness must not resolve them.
- Digest equality proves byte identity against the declared digest, not provenance, ownership or license rights.

## 6. Required rejection cases

The harness rejects source Manifest digest/size mismatch, resource byte digest/size mismatch, invalid Base64, unsafe canonical paths, duplicate resource identities/paths, catalog snapshot digest mismatch, duplicate catalog identities and unresolved catalog dependency references.

## 8. Not implemented / Not tested

- Production package ingestion and content-addressed object storage;
- actual Manifest bytes from a package archive and end-to-end builder wiring;
- resource bytes bound to every Resource Catalog entry (current bytes are representative fixture records);
- external URL retrieval, SSRF/IP/DNS protections and redirects;
- archive format canonicalization and extraction safety;
- signature/attestation verification, trust roots and key revocation;
- legal License/Provenance adjudication;
- production catalog snapshot profile approval.

## 9. Decision impact

DEC-27 remains OPEN: snapshot digest profile is a candidate and does not choose the final Package Digest profile. DEC-28/29 remain OPEN. DEC-17 remains OPEN for scientific numeric representation. AUD-001/AUD-002 are not closed by this fixture harness.


## 10. CI evidence — Run #193

GitHub Actions [Run #193](https://github.com/liucaidong/stem-lab/actions/runs/41428620138) completed SUCCESS. Logs explicitly confirm:
- exact source Manifest bytes, size, SHA-256 and Package identity;
- embedded resource byte size and SHA-256 for two fixture blobs;
- canonical path validation;
- pinned Catalog Snapshot JCS candidate digest and catalog/dependency order invariance;
- 8 rejection cases;
- the R03.45 Builder→JCS/CBOR candidate pipeline and R03.46 Python/Node Golden Vectors still pass;
- R03.44 cross-module audit still reports 14 checks and 12 recorded findings, with `CONDITIONAL_NOT_READY; production_ready=False`.

The first run (Run #192) failed because the fixture still had a zero placeholder snapshot digest. The validator exposed the computed expected digest; the fixture was then pinned to that value and Run #193 passed. The failed run remains visible as audit history.

## 11. R03.47 result

The fixture harness now proves byte-level SHA-256/size checks and a deterministic Catalog Snapshot pin for the included examples. It does not yet bind every Catalog resource to actual bytes, ingest package archives, resolve object storage, or establish a production trust chain. AUD-001 and AUD-002 remain OPEN.
