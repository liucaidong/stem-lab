# R03.52.1 Worker Runtime Lifecycle & Supervision Reference

- Date: 2026-11-02
- Status: Adapter-neutral executable reference + deterministic lifecycle tests; not production-ready
- Parent: R03.51
- Product Code Freeze: ACTIVE
- P3.17: OUT OF SCOPE / MUST NOT ENTER
- Related decisions: ADR-001, ADR-005, DEC-03, DEC-04, DEC-05, DEC-13, DEC-19, DEC-30

## 1. Objective and boundary

Turn the R03.51 durable Job/Lease/Fencing contract into a process lifecycle contract without selecting a production language protocol, database migration stack, broker, deployment platform, or observability vendor.

This increment implements only an adapter-neutral single-slot orchestration core. It does not implement a PostgreSQL Store adapter, process supervisor, Scheduler service, broker relay, production handler sandbox, or product functionality.

## 2. Runtime responsibilities

The process core owns:
- stable worker identity supplied by deployment configuration;
- stop-claiming behavior after shutdown request;
- bounded claim/poll loop;
- dispatch by registered job_type;
- lease heartbeat while handler executes;
- fail-closed behavior on heartbeat false/exception;
- no completion/failure mutation after lease loss;
- sanitized error classification through an injected policy;
- graceful drain: active handler may finish while heartbeat continues; shutdown does not forcibly release a lease.
- Store adapter calls MUST have explicit network/statement timeouts; in particular renew must return within the heartbeat budget so shutdown can join the heartbeat thread.

The Store adapter MUST independently enforce tenant + job + owner + epoch + database-clock expiry on renew, complete and fail. Runtime-side checks are advisory and never replace database fencing.

## 3. Lifecycle invariants

1. No claim after shutdown is observed.
2. Handler work runs outside claim/renew transactions.
3. Heartbeat interval is strictly shorter than lease duration.
4. Any renewal false result or exception marks the lease lost.
5. Lease-lost work MUST NOT complete or transition retry/DLQ through this runtime.
6. Handler exceptions are mapped to a bounded safe error contract; raw exception text is not persisted by the runtime.
7. Missing handler is a non-retryable configuration failure.
8. Shutdown stops new claims but does not falsely mark in-flight work complete or release its lease.
9. Store completion remains the final authority and may reject a result as stale/expired.

## 4. Executable reference

- `runtime/worker_runtime.py`: adapter-neutral lifecycle orchestration.
- `scripts/test_worker_runtime.py`: standard-library unit tests with deterministic fake Store.
- CI runs the lifecycle tests; these tests do not prove PostgreSQL adapter, broker, OS signal delivery, multi-process scheduling, or external side-effect fencing.

## 5. Failure and shutdown semantics

| Condition | Runtime action | Persistence action |
|---|---|---|
| No due job | Return idle; poll after bounded interval | None |
| Handler success | Stop heartbeat; request fenced completion | Store validates current lease |
| Handler exception | Classify and request fail transition | Store validates current lease |
| Heartbeat returns false | Mark lease lost; do not complete/fail | Job remains for expiry/reclaim |
| Heartbeat raises | Treat as lease lost | Job remains for expiry/reclaim |
| Shutdown requested | Stop new claims; drain active handler | No synthetic completion/release |
| Handler missing | Non-retryable configuration failure | Store may DLQ under policy |

A hard process termination can interrupt the handler. The lease is intentionally left to expire and be reclaimed. This is at-least-once execution; handlers must use idempotency keys or downstream fencing for external effects.

## 6. Explicit limitations / open decisions

- DEC-03 remains OPEN: Python is used only for a reference orchestration implementation, not selected as the production Worker protocol/runtime.
- DEC-04 and DEC-19 remain OPEN: no production connection pool, migration, trusted tenant context, or RLS trust boundary.
- DEC-05 and DEC-30 remain OPEN: no Broker/Relay/Consumer implementation or production delivery guarantee.
- DEC-13 remains OPEN: no OTel SDK/exporter or backend selected.
- No concurrency pool or per-tenant fairness policy is implemented.
- No process-level signal adapter or container orchestrator integration is implemented.
- No handler sandbox/resource quota is implemented.
- No proof of bounded shutdown time exists; a non-cooperative handler can delay graceful drain. Deployment termination grace must exceed the handler's own cooperative cancellation policy or rely on process kill + lease expiry.

## 7. Verification

CI must execute `python scripts/test_worker_runtime.py` and retain the PostgreSQL R03.51 suite. Required tests:
- idle claim;
- success completion with original epoch;
- sanitized exception classification;
- heartbeat loss prevents completion/failure;
- shutdown prevents new claim;
- shutdown drains an already active handler while heartbeat remains active;
- heartbeat transport exception fails closed;
- missing handler fails closed;
- invalid heartbeat/lease configuration rejected.

Passing unit tests verify the orchestration core only. They do not close production readiness or existing AUD findings.
