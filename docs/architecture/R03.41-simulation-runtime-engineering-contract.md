# R03.41 Simulation Runtime Engineering Contract

- 版本：0.1；日期：2026-11-02
- 状态：CI Run #137通过Runtime Execution静态契约验证（局部）；未实现Worker或Scheduler
- 关联：R03.7、R03.15、R03.20 DEC-03/05/10/17/30、R03.32、R03.38、R03.39、R03.40

## 1. 职责边界

Runtime Control Plane负责Command授权、状态迁移、Lease/Epoch/Fencing、Deadline和Event；Worker负责受限执行并返回候选结果；Scientific Solver负责数值算法；Renderer负责视觉呈现；Learning/教学流程负责任务编排与反馈。任何一层不得绕过Command Handler直接写权威Session状态。

## 2. Execution Lifecycle

状态候选：queued → leased → starting → running ↔ checkpointing → cancelling → cancelled；正常终态为succeeded/failed/timed_out。实际允许迁移必须服从R03.7/R03.15状态矩阵；本文件不复制或覆盖既有状态机。

Worker每次租约包含worker_id、lease_id、epoch、fencing_token、issued_at和expires_at。Worker结果提交必须校验Execution、Session stateVersion、Epoch、当前Lease及Fencing Token；过期或旧Token结果拒绝。

## 3. Resource Quota与Timeout

Execution Contract明确mode、wall_clock_timeout_ms、cpu_time_limit_ms、memory_limit_mb、output_limit_bytes、max_steps和cancellation_mode。Wall-clock timeout与CPU time是不同预算；超时后由Runtime记录timed_out，不允许Worker自行改写Session状态。

取消模式：cooperative允许Solver在安全检查点停止；immediate要求Worker进程/任务强制终止。强制终止后仍需Fencing，迟到结果不能提交。

## 4. Simulation Time与Wall-clock Time

Simulation Time是模型域时间，具有数值和单位，可能暂停、加速或离散推进；Wall-clock Time是调度、租约、超时、审计和资源预算时间。两者不得混用或互相推导。Observation必须明确simulation_time与observed_at/wall-clock timestamp。

## 5. Checkpoint / Recovery / Replay

Checkpoint记录Execution ID、input state digest、solver id/version、simulation time、state version、epoch/fencing token、checkpoint sequence和内容Digest。恢复必须验证Checkpoint属于同一Execution/输入快照/模型版本，并由新Lease/更高Epoch接管。Deterministic Replay需要固定输入Digest、Solver版本、seed、数值配置和执行环境声明；跨平台位级一致性仍需R03.42验证。

## 6. 机器可读契约与验证

- contracts/runtime-execution-contract.schema.v1alpha1.json；
- contracts/examples/runtime-execution-contract.fixtures.v1alpha1.json；
- scripts/validate_runtime_execution_contract.py。

Fixture验证Lease到期、Deadline、资源配额、Fencing Token、Simulation Time、Checkpoint配置和Deterministic Replay Seed。它不执行Runtime、Worker、Solver、Checkpoint持久化或真实恢复。

## 7. Not Tested
