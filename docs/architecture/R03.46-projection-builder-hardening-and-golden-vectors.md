# R03.46 Projection Builder Hardening & Golden Vector Engineering

- Version: 0.1
- Date: 2026-11-02
- Status: Cross-language golden-vector harness; candidate profiles only
- Parent: R03.45
- Related risks/decisions: AUD-001, DEC-27, DEC-28, DEC-29
- Product Code Freeze: ACTIVE

## 1. Objective

Turn deterministic serialization from a same-process repeatability claim into a reproducible, cross-language byte-and-digest check. This stage adds fixed expected vectors and two independent execution paths: Python (rfc8785, cbor2) and Node.js built-in implementations for the vector subset.

## 2. Golden vector corpus

File: contracts/examples/package-canonicalization-golden-vectors.v1alpha1.json.

JCS vectors cover:
- UTF-16 property-key ordering, BMP and supplementary Unicode, escaped newline and quote;
- ECMAScript number serialization, exponent thresholds, negative zero and representative binary64 values;
- nested objects, arrays, booleans and null.

CBOR vector covers:
- Core deterministic map-key ordering (encoded key length then bytewise order);
- text, arrays, booleans, null, positive and negative integers;
- shortest-width integer heads for the represented values.

Each vector fixes canonical bytes (hex) and a domain-separated SHA-256 digest. The expected bytes/digests are literals, not generated at test runtime.

## 3. Independent verifiers

- Python verifier: scripts/validate_package_canonicalization_golden_vectors.py, using pinned rfc8785==0.1.4 and cbor2==6.1.5 libraries.
- Node verifier: scripts/verify_package_canonicalization_golden_vectors.mjs, using Node built-ins and a separately authored JCS/CBOR subset encoder.
- Both implementations compare against the same fixed bytes and digest literals.
- Node JCS uses ECMAScript number-to-string and JavaScript UTF-16 key ordering; it rejects non-finite numbers and malformed surrogate strings.
- Node CBOR currently covers only the integer/text/map/array/bool/null subset represented by the corpus.

This is cross-language evidence for the covered vector set, not proof of full RFC conformance for every possible JSON/CBOR value.

## 4. Digest framing

For profile P and canonical bytes B:

SHA-256(UTF8("stemlab-package-digest") || 0x00 || ASCII(P) || 0x00 || B)

The vector file fixes both profile identifiers:
- rfc8785-jcs
- cbor-rfc8949-core

The profile identifier is part of the digest domain. The two profiles intentionally produce different byte streams and different digest values for equivalent data.

## 5. Important semantics and limitations

- JCS preserves Unicode string values; it does not perform NFC normalization. Path NFC validation remains an upstream projection invariant.
- Object property ordering is not array ordering. Resource and dependency arrays must already be normalized by R03.35/R03.45 rules before serialization.
- The number vector includes negative zero, which canonicalizes to 0.
- The vector set does not yet define how scientific decimal quantities beyond binary64 precision are represented. DEC-17 remains OPEN.
- The CBOR vector intentionally excludes floating-point values, tags, byte strings, indefinite-length items, duplicate map keys and bignums. These require a separately reviewed profile and expanded independent vectors.
- No signature or attestation is created or verified by this stage.

## 6. CI

The existing canonicalization candidate validator will consume the fixed vectors using Python. A separate Node.js 22 job step executes the independent verifier. CI success proves the checked-in vectors match both implementations on the runner used; it does not close DEC-27 or establish a production digest profile.
