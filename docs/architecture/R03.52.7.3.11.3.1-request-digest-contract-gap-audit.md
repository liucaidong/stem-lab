# R03.52.7.3.11.3.1 — Request Digest Contract Gap Audit

**Status:** SOURCE_AUDIT_PARTIAL / DESIGN_GAPS_CONFIRMED / PRODUCTION_NOT_READY
**Audited refs:** PR #13 c38f22d72a54934dbca80759db1dd85b3903163c; PR #14 cda9a05ea0ea06b4435fb05b5d3815e0913dd3ef.

## Verified facts

1. The v2alpha1 schema has additionalProperties=false and v=2, but no request_digest or signed idempotency_key.
2. The PostgreSQL fixture signs the payload segment with Ed25519. Its Python canonical_payload uses json.dumps(sort_keys=True,separators=(",",":"),ensure_ascii=False).encode("utf-8").
3. PostgreSQL verify_v2 validates the signed claim shape, key lifecycle, time window, action/resource relationships and Ed25519 signature. It does not independently reconstruct a business Request Envelope or calculate SHA-256 over operation arguments.
4. authorize_v2 compares signed Job and operation IDs to transaction-local GUC values, checks Job lease fencing, then inserts the signed token into nonce_ledger. Caller-settable GUC values are not trusted authorization evidence by themselves.
5. The Runtime RLS helper checks a nonce-ledger row bound to pg_current_xact_id() and the expected tenant/job/session/action/resource/operation. The GUC supplies a token selector; it cannot manufacture a valid ledger row.
6. renew_v2, retry_v2, dead_letter_v2, Outbox dispatch/ack and DLQ replay accept business parameters separately from signed claims. They are not covered by a signed request digest.
7. CompleteJobCommand includes expected_session_revision, result_ref, idempotency_key and request_digest. FailJobCommand includes error_code, safe_message, retryable, retry_delay_seconds and idempotency_key. The Store protocol does not define one shared signed Request Envelope for every operation.
8. The fixture Receipt primary key is (tenant_id, operation_id), not the required tenant + idempotency key identity.
9. The historical CI run reports 46/46 resource authorization tests. New tests must be additive.
10. CI runs the PostgreSQL resource authorization harness in tenant-ed25519-verifier and broader contracts in validate-contracts.

## Operation argument inventory

| Action | Source-observed inputs | Digest binding |
|---|---|---|
| Claim v1alpha1 | assignment capability, supported job types, lease duration | Excluded from v2alpha2; separate contract only |
| Job Renew | lease duration | integer seconds |
| Job Complete | expected session revision, result reference, idempotency key | revision + result_ref + key |
| Job Fail | error code, safe message, retryable, retry delay | all fields; delay integer microseconds |
| Job Retry | delay seconds, error code | both |
| Job Dead-letter | error code, terminal reason | both |
| DLQ Replay | DLQ resource and operation identity | empty argument object |
| Outbox Dispatch | lease duration | integer seconds |
| Receipt Reconcile | Receipt resource and operation identity | empty argument object |
| Outbox Ack | event resource and operation identity | empty argument object |

## Security findings

- F-DIG-01: Business arguments are not cryptographically bound by v2alpha1.
- F-DIG-02: Python JSON sorting is not a cross-language canonicalization contract.
- F-DIG-03: PostgreSQL independently verifies Ed25519 but does not independently recompute a request digest.
- F-DIG-04: Receipt primary key is operation identity, not idempotency identity.
- F-DIG-05: Complete and other operations use different persistence surfaces; common transaction semantics are unproven.
- F-DIG-06: Several PL/pgSQL handlers catch WHEN OTHERS and return false/null. The caller must not commit after a false result if the contract requires all-or-nothing behavior; prove rollback with persisted-state assertions.

**Disposition:** G1 partially satisfied for source paths reviewed. Caller call-site inventory, full Receipt reconciliation path, nonce transaction semantics and current CI rerun remain pending. No production acceptance is implied.
