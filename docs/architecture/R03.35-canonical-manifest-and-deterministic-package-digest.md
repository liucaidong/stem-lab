# R03.35 Canonical Manifest 与 Deterministic Package Digest

- 版本：0.1；日期：2026-11-02
- 状态：CI Run #95双候选重复性测试通过（局部）；Canonical Projection草案；DEC-27保持OPEN
- 关联：R03.8、R03.20 DEC-27、R03.30、R03.31、R03.34

## 1. 目标与边界

定义与传输格式分离的Canonical Manifest Projection，明确资源排序、Digest输入范围、排除字段和候选确定性序列化。此阶段比较RFC 8785 JCS与RFC 8949 Deterministic CBOR；不因存在测试实现而批准任一方案。

## 2. 候选序列化方案比较

| 维度 | RFC 8785 JCS | RFC 8949 Core Deterministic CBOR | 确定性归档 |
|---|---|---|---|
| 数据模型 | I-JSON / JSON | CBOR数据模型 | 文件系统/归档条目 |
| 属性排序 | 递归JSON对象属性排序；UTF-16 code unit顺序 | Map key按确定性编码字节序 | 必须额外定义条目排序 |
| 数值 | IEEE-754 binary64语义及ECMAScript序列化 | Preferred serialization；浮点最短保值编码 | 取决于归档元数据和文件内容 |
| Unicode | 保留字符串原样，不做Unicode normalization | UTF-8文本字符串；需定义应用层字符串约束 | 文件名编码/平台行为需要约束 |
| 互操作 | JSON生态与现有Schema/API契合 | 二进制工具链、JSON映射和Tag策略需要约定 | 常见工具易用，但压缩器/平台差异明显 |
| 主要风险 | 大整数/精度限制；UTF-16排序；NaN/Infinity拒绝；实现需严格符合规范 | 必须明确确定性profile、浮点/Tag策略、映射规则 | 时间戳、权限位、条目顺序、压缩级别和实现版本影响字节 |
| 适配判断 | 当前JSON契约的候选优先项 | 对高精度/二进制数据有吸引力，适合独立评估 | 不建议作为语义Manifest规范的唯一来源 |

RFC 8785是Informational RFC，不是Standards Track；它约束I-JSON、binary64数值和Unicode处理。RFC 8949允许协议定义确定性格式，核心规则包括preferred serialization、禁止indefinite-length及Map key确定性排序。两者均需定义项目级字段投影与资源列表顺序。

## 3. Canonical Projection

Schema：contracts/package-canonical-manifest.schema.v1alpha1.json。

Projection字段：
- projection_version；
- package：api_version、package_id、package_version；
- content：Package的全部语义内容字段；
- resources：规范化资源记录；
- dependency_closure：R03.34根可达闭包中的资源身份集合。

资源记录包含path、resource_type、resource_id、version、media_type、size_bytes、digest和license_id。License ID作为发布内容语义纳入摘要；许可证正文、授权合同和个人信息不进入公开Projection。

## 4. 排序和路径规范

1. 资源path必须为POSIX相对路径；拒绝绝对路径、反斜线、空段、.、..。
2. path必须已经是Unicode NFC；验证器不静默改写路径。
3. 拒绝完全重复路径和casefold碰撞，避免跨平台大小写差异。
4. resources按规范化path UTF-8字节序升序。
5. dependency_closure按(resource_type, resource_id, version, digest)各字段UTF-8字节序依次升序。
6. 对象属性排序由被选序列化规范负责；不得把数组排序规则与Map/Object键排序混为一谈。
7. 同一资源在多条边被引用时，在dependency_closure中只出现一次。

## 5. Digest覆盖范围

Digest输入是Canonical Projection的确定性序列化字节。候选域分离前缀：

stemlab-package-digest\0{profile-id}\0{canonical-bytes}

Digest算法候选为SHA-256，格式为sha256: + 64位小写hex。

**纳入：** Package schema version、Package ID/Version、所有语义内容字段、资源规范化路径/类型/版本/MIME/size/Digest/License ID、完整依赖闭包。

**排除：** 顶层package_digest自身、signature、attestation、signer/key metadata、created_at/updated_at/published_at/build timestamp、CI run URL、validation report digest、临时本地路径和下载URL。外部资源的内容Digest必须纳入；可变URL不作为内容身份。

排除字段通过显式Projection构造实现，不采用对任意JSON递归删除所有名为timestamp或signature的键，以免误删合法科学内容。

## 6. 双候选实现与验证

- Schema：contracts/package-canonical-manifest.schema.v1alpha1.json
- Fixture：contracts/examples/package-canonical-manifest.fixtures.v1alpha1.json
- 验证器：scripts/validate_package_canonical_manifest.py
- 候选库：rfc8785==0.1.4、cbor2==6.1.5，仅用于比较Spike，不构成生产技术选型。

验证器对相同Projection分别生成JCS与CBOR候选字节，检查资源/依赖输入顺序扰动后规范化结果不变、同一候选重复序列化字节一致、资源Digest变化导致顶层摘要变化；同时拒绝路径穿越、重复路径、大小写冲突、非NFC路径和非有限数值。

该测试是单一Python runner上的候选实现重复性测试，不是跨语言互操作证明。正式关闭DEC-27还需要至少两种独立语言实现对同一Golden Vector产生完全相同字节和Digest。

## 7. ADR候选结论

候选推荐：先以JCS作为JSON契约互操作基线进行跨语言Spike，同时保留CBOR候选并测量编码大小、精度边界和实现一致性。若业务数值超出I-JSON binary64适用边界，必须先定义数值字符串/定点表示策略，不能静默舍入。当前证据不足以冻结方案。

DEC-27仍OPEN；DEC-28签名/Attestation和DEC-29 License/Provenance仍OPEN。任何签名必须绑定profile ID、digest algorithm、Package identity和Digest值，避免算法/版本歧义。

## 8. Not Tested

- 第二种语言的独立Canonicalizer；
- 大整数、浮点边界、负零、指数表示、Unicode排序Golden Vector；
- 真实Package Manifest与R03.34 Graph自动投影；
- 资源路径跨OS互操作；
- 签名、Attestation、License门禁和生产发布器；
- 大规模资源清单性能与内存峰值。
