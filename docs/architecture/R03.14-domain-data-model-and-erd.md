# R03.14 核心领域数据模型与关系设计

- 版本：0.1；日期：2026-11-02
- 状态：逻辑数据模型草案；需ERD/迁移/真实RLS测试
- 关联：R02.3、R03.7–R03.11、R03.13

## 1. 建模原则

1. Tenant是业务数据隔离边界；租户业务表必须具备tenant_id或通过强约束关系继承租户归属。
2. User身份与Tenant Membership分离；一个用户可属于多个机构。
3. 业务对象ID使用稳定不可猜测标识；不要把顺序自增ID暴露为授权凭据。
4. 版本化内容（Package、Model、Rubric）发布后不可变。
5. Session、Command、Event、Execution和Observation形成可追溯链。
6. 外部系统标识保存在Integration Mapping，不污染内部主键。
7. 大体积数据放Object Storage，数据库保存元数据、digest和授权索引。
8. 删除采用生命周期策略和审计，不以级联删除破坏学习证据。

## 2. 核心实体分组

### Identity与组织
Tenant、User、ExternalIdentity、Membership、RoleBinding、Policy、IntegrationConnection、ExternalIdMapping。

### Learning
Course、Class、Enrollment、Assignment、AssignmentPackageLock、ExperimentAttempt、Notebook、NotebookVersion、Submission、Rubric、RubricVersion、Assessment、Feedback。

### Content
ExperimentPackage、PackageVersion、PackageDependency、PackageRelease、ValidationReport、ScientificModel、ModelVersion、ModelArtifact、SceneVersion、InstrumentDefinition、WorkflowVersion、Asset、AssetLicense。

### Runtime与科学数据
RuntimeSession、RuntimeState、RuntimeCommand、CommandReceipt、RuntimeEvent、OutboxMessage、Execution、WorkerLease、SolverRegistryEntry、Observation、ObservationSeries、Dataset、DerivedValue、Snapshot。

### Governance与运营
AuditRecord、QuotaLedger、UsageMetric、RetentionPolicy、DeletionRequest、Incident、ApprovalRecord。

## 3. 关键关系

- Tenant 1:N Membership；User 1:N Membership。
- Tenant 1:N Course；Course 1:N Class；Class 1:N Enrollment。
- Course 1:N Assignment；Assignment固定引用一个PackageVersion。
- Assignment 1:N ExperimentAttempt；Attempt 1:N RuntimeSession（允许重试创建新Session）。
- RuntimeSession固定引用PackageVersion、ModelVersion、Solver版本和依赖清单。
- RuntimeSession 1:N RuntimeCommand、RuntimeEvent、Execution、Observation、Snapshot。
- RuntimeCommand 1:1 CommandReceipt；RuntimeEvent和OutboxMessage在同一事务生成。
- Execution 1:N WorkerLease attempt；结果提交绑定唯一有效Execution/epoch。
- Observation可引用Execution、ModelVersion和仪器来源；ObservationSeries聚合多个Observation。
- Notebook 1:N NotebookVersion；Submission固定引用NotebookVersion、Observation快照和RubricVersion。
- Submission 1:N Assessment revisions；每次评分不可覆盖历史评分。
- PackageVersion 1:N PackageDependency；依赖项必须固定版本/digest。

## 5. 关键唯一约束与索引候选

- Membership：unique(tenant_id,user_id)；
- ExternalIdentity：unique(provider,issuer,subject)；
- Enrollment：按业务规则unique(class_id,user_id)；
- PackageVersion：unique(package_id,version)，且发布后digest不可变；
- RuntimeCommand：unique(tenant_id,session_id,idempotency_key)；
- CommandReceipt：unique(command_id)；
- RuntimeEvent：unique(tenant_id,aggregate_type,aggregate_id,aggregate_sequence)；
- Execution：unique(execution_id)，并索引(session_id,status,created_at)；
- WorkerLease：索引(execution_id,lease_expires_at)，fencing_token单调约束；
- Observation：按(session_id,simulation_time,sequence)建立查询索引；
- Submission：按(attempt_id,submission_version)唯一；
- Assessment：按(submission_id,assessment_revision)唯一；
- AuditRecord：按(tenant_id,occurred_at,actor_id)索引。

所有唯一约束需纳入tenant范围，避免不同租户标识冲突或侧信道。

## 6. 事务边界

### Command事务
锁Session→验证Tenant/权限→验证幂等键/请求哈希→校验stateVersion→更新状态→写Event→写Receipt→写Outbox→提交。

### Result Commit事务
验证Execution/epoch/lease/input stateVersion→验证结果引用和digest→写Observation/Execution状态→更新RuntimeState/Session→写Event/Outbox→提交。大文件上传在事务外完成，事务内只提交已校验的对象引用；失败时需清理孤儿对象。

### Submission事务
锁Attempt→校验截止/尝试策略→固定NotebookVersion、Observation Snapshot和RubricVersion→写Submission→写事件/审计→提交。

### Assessment事务
校验教师权限→固定Submission和Rubric版本→写新Assessment revision→发布Feedback→审计。重评不得覆盖既有记录。

## 7. 删除、归档与保留

Tenant停用、User删除、课程归档、Package撤回、Submission撤销和数据删除是不同操作。必须建立RetentionPolicy和DeletionRequest工作流，处理数据库、对象存储、缓存、搜索索引、导出副本和备份到期。法律保留例外必须记录依据、范围、批准人和期限。

## 8. RLS策略要求

每张租户业务表启用并强制RLS；策略同时检查tenant_id和必要的资源关系。后台跨租户任务使用独立服务角色和审计。真实PostgreSQL测试覆盖连接池复用、事务回滚、后台任务、只读副本和对象存储签名URL。
