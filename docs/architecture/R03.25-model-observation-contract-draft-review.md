## 2. ScientificModel契约设计

Schema当前定义：
- Model身份、版本、领域和标题；
- modelKind：algebraic、ode、discrete-event；
- expressionLanguage固定为声明式 `stemlab-expression-ast/v1`；
- parameters、variables、equations、constraints和initialConditions；
- validityDomain中的assumptions/exclusions；
- solverRequirements与validationCases；
- provenance和expertReviewRequired。

方程通过不可变 `expressionRef(id, version, digest)` 引用表达式资源，而不是把任意脚本字符串放入模型。表达式AST的具体语法、解释器和安全策略尚未定义；不得将当前Schema理解为已支持可执行表达式。

## 3. Observation契约设计

Observation区分：
- 仿真时间 `simulationTime` 与平台观测时间 `observedAt`；
- 来源类型 instrument/model/derived/imported；
- 质量状态 valid/estimated/invalid/out-of-range；
- 标量 `data.value` 与大型数据集 `data.valueRef`。

Schema要求标量值和数据引用二选一，不能同时缺失或同时存在。单位字段必须显式填写；无物理单位时使用明确的dimensionless标记。可选uncertainty字段用于表达标准不确定度及适用的置信水平。

`tenantId`属于持久化观察记录的服务端归属字段，必须从可信认证/执行上下文派生；客户端不得通过写入请求自行声明租户身份。此Schema是持久化/事件数据结构草案，不等于客户端可写入全部字段的API请求Schema。

## 4. 与现有契约的关系

- ExperimentPackage的model资源引用继续通过id/version/digest固定ScientificModel版本。
- ScientificModel的validationCases引用不可变参考算例资源。
- Observation记录session、execution、package/model版本和stateVersion，以支持结果溯源。
- Runtime Event可携带Observation引用或摘要，不应把大体积时间序列直接塞入事件Payload。

## 5. 当前Schema无法独立保证的语义

必须由后续Semantic Validator、数据库约束或运行时策略完成：
1. equation.inputs/outputs/constraint.targetIds确实引用已声明参数/变量；
2. equation依赖图不存在不允许的循环或未定义变量；
3. 输入/输出单位与quantityKind量纲一致，表达式两侧量纲一致；
4. 参数minimum不得大于maximum，defaultValue落在范围内；
5. expressionRef与validationCases资源存在且digest对应实际字节；
6. expression AST不含未批准节点、函数、资源访问或任意代码执行能力；
7. Observation的tenant/session/execution/package/model引用真实存在且归属一致；
8. uncertainty单位与Observation值单位一致；
9. valueRef对象大小、媒体类型、授权和digest得到服务端校验；
10. observedAt、createdAt、simulationTime的时间语义及排序规则由服务端保证。

## 6. 待补充的负向测试

- ScientificModel：未知变量引用、重复ID、非法modelKind、缺失expression digest、非法单位、参数范围倒置、未批准表达式节点；
- Observation：value/valueRef均缺失、两者同时存在、非法日期时间、负simulationTime、未知sourceType、错误digest、越权tenant/session引用；
- Semantic Validator：量纲不一致、循环依赖、未解析资源引用、默认值越界和表达式资源撤回。
