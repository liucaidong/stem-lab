## 5. 当前发现与限制

1. Package Schema 的 `$id` 仍使用 `example.invalid` 占位域名，正式发布前必须替换为项目控制的稳定 URI。
2. `gradeBand.min` 与 `gradeBand.max` 的大小关系由独立语义校验器检查；若未来允许部分边界为空，需继续明确其业务语义。
3. Schema的digest正则只检查格式；Run #60新增对一个本地测试Asset实际文件字节的SHA-256/size重算，但尚未覆盖所有ResourceRef、远程对象、依赖闭包或顶层Package Digest。
4. Package 资源引用存在性、依赖锁、许可策略、签名、撤回状态和科学正确性不属于当前 JSON Schema 可独立证明的范围。
5. 本报告原始执行范围仅覆盖通用Event Envelope；R03.26后续新增SessionStarted、ExecutionSucceeded、ObservationRecorded三种Payload Schema/Fixture及Registry驱动验证，其他事件类型和Consumer幂等/乱序/重放测试仍未完成。
6. OpenAPI 若干响应只有 description，没有可供客户端生成和互操作测试使用的完整响应 Schema；认证、资源级授权、统一错误模型、分页边界和限流约束也未完整定义。
7. Run #41/#42/#49/#53/#60/#62/#63/#65/#68成功；Run #42/#49/#53/#60/#62/#63使用`requirements-contract-validation.lock.txt`固定直接及传递依赖版本。锁文件固定版本但尚未采用pip hash校验。Run #45–#48曾因OpenAPI value_ref块缩进错误而失败，修正后Run #49通过；失败和修复均保留在Git历史中。
