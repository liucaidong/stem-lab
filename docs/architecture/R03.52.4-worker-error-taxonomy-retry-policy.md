# R03.52.4 Worker Error Taxonomy & Retry Policy Registry

- Status: Versioned policy contract + executable reference + tests; CI pending

## 1. Objective

Replace ad-hoc exception interpretation with a versioned, explicit error-code policy boundary. The registry returns stable error codes, safe retry messages, retryability and capped full-jitter delay. It does not inspect or persist raw exception text.

## 2. Policy semantics

- A handler/adapter maps an exception to a stable error_code using a separately reviewed classifier.
- The registry maps known codes to explicit retry policies.
- Unknown codes map to a non-retryable UNCLASSIFIED_ERROR default.
- Retryability is disabled when the Job's persisted attempt_count reaches maximum_attempts.
- For retryable attempts n, ceiling = min(max_delay, base_delay * 2^(n-1)).
- Delay = random_value * ceiling, where random_value is in [0,1].
- Non-retryable policies have zero delay bounds.
- Safe messages are registry-owned; exception messages and payload content are never copied.

The Job row remains authoritative for attempt_count and maximum_attempts. Policy does not override the persisted Job budget.

## 3. Executable assets

- contracts/worker-retry-policy.schema.v1alpha1.json: Draft 2020-12 registry schema.
- contracts/worker-retry-policy.v1alpha1.json: illustrative candidate error taxonomy and policies.
- runtime/retry_policy.py: policy evaluation with injectable random source.
- scripts/validate_worker_retry_policy.py: schema, uniqueness and policy invariant validation.
- scripts/test_worker_retry_policy.py: retry, jitter, cap, exhaustion, unknown-code and invalid-input tests.

The sample policy is a reference candidate, not a production error catalog. No exception classifier is selected or wired to production handlers in this increment.

## 4. Explicit limitations

- No global/tenant-specific policy rollout or live reload.
- No policy signature, approval workflow or audit log.
- No production classifier mapping arbitrary exceptions to codes.
- No database migration or policy version pin stored on each Job.
- No metrics/alerting for retry rates or DLQ growth.
- No DLQ replay operator or authorization.
- DEC-03/13/19/30 remain OPEN.

## 5. Verification

Required tests cover known policy lookup, exponential ceiling/cap, full-jitter bounds, permanent errors, maximum-attempt exhaustion, unknown-code fail-closed behavior, secret-safe messages, invalid attempt budgets, invalid RNG values and invalid policy configuration.

Passing tests verify policy evaluation only, not production error classification or operational rollout.
