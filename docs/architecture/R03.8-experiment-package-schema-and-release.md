# R03.8 Experiment Package规范与内容发布协议

- 版本：0.1；日期：2026-11-02
- 状态：契约草案；Schema需技术Spike冻结
- 关联：R02.3 FR-PKG/FR-AUTH、R02.5 E2E-06、R03.6 TF-04/10

## 1. 目标与安全边界

Experiment Package是实验内容的声明式、可校验、可版本化交付单元。它描述学习目标、模型引用、场景、仪器、工作流、评价和资源，不承载任意生产端可执行代码。

Package内容一律视为不可信输入。发布前必须经过语法、Schema、引用、语义、许可、安全、Runtime Preflight和科学验证。运行时只解析受支持的声明，不执行Package内任意Shell、Python、JavaScript或动态插件代码。

## 2. 逻辑目录结构

~~~text
experiment-package/
  manifest.yaml
  learning-objectives.yaml
  model/
    model-ref.yaml
    validation-cases/
  scene/
    scene.yaml
  instruments/
    instruments.yaml
  workflow/
    workflow.yaml
  assessment/
    rubric.yaml
  assets/
  locales/
  tests/
  provenance/
    licenses.yaml
    sources.yaml
~~~

实际发布包应打包为确定性归档或内容寻址资源集合；目录结构是逻辑组织，不要求运行时直接读取工作目录。

## 3. Manifest字段基线

必需字段：
- apiVersion：Package契约版本；
- kind：固定为ExperimentPackage；
- metadata.id：全局稳定标识；
- metadata.version：不可变语义版本；
- metadata.title、description、subject；
- metadata.gradeBand：可选，须声明适用性依据；
- spec.learningObjectives：目标引用；
- spec.model：Model ID和精确Version/Digest；
- spec.scene：Scene资源引用；
- spec.instruments：仪器资源列表；
- spec.workflow：实验流程资源；
- spec.assessment：Rubric资源；
- spec.assets：资源清单；
- spec.runtime：允许的执行模式、reset policy和能力要求；
- spec.validation：验证案例和专家审核状态引用。

资源引用必须包含稳定ID、版本和digest；禁止使用浮动latest引用。所有引用均需在发布时解析并锁定。

## 4. 版本和内容寻址

- Package ID标识逻辑实验，不随版本变化；
- Package Version标识不可变发布版本；
- Digest覆盖规范化Manifest和全部依赖内容；
- 同一ID/version若内容digest变化，发布必须失败；
- 修改内容生成新版本，不覆盖历史版本；
- Assignment和Session固定引用Package Version及完整dependency lock；
- 撤回只影响未来分配/启动策略，不删除历史记录和审计。

具体语义版本策略、哈希算法、归档规范和签名格式须在Schema ADR中冻结。不得在文档阶段假定某种算法已经落地。

## 5. 校验流水线

1. Syntax：YAML/JSON解析、重复键和编码检查；
2. Schema：apiVersion、必填字段、类型、枚举和约束；
3. Reference：所有Model/Scene/Instrument/Workflow/Rubric/Asset引用存在且版本明确；
4. Semantic：变量、单位、端口、仪器量程、流程节点和模型接口兼容；
5. License/Provenance：资产来源、许可、署名和再分发权满足策略；
6. Safety：文件类型、大小、恶意内容、外链、路径穿越和资源耗尽风险；
7. Runtime Preflight：能力声明、浏览器/Worker支持和资源配额；
8. Scientific Validation：参考算例、单位/量纲、约束和专家签核；
9. Review：内容和学科审批；
10. Release：生成不可变版本、digest、签名/审批记录和依赖清单。

任一阻断级校验失败不得发布。警告必须有明确责任人和批准策略，不能静默忽略。

## 6. Runtime解析与Session快照

Session创建时解析Package和全部依赖，保存：
- package_id/version/digest；
- model_id/version/digest；
- scene/instrument/workflow/rubric资源版本；
- solver capability和选定solver版本；
- validation report ID；
- locale和关键配置；
- 解析时间和发布来源。

后续Catalog更新不得改变既有Session。资源不可用时应返回明确错误，不允许悄悄回退到新版本。

## 7. 发布、撤回与回滚

最小P0发布路径允许受控内部工具/CLI：创建草稿→提交校验→审核→发布。P1再提供完整可视化Author Studio。发布权限与内容编辑权限分离；审核人不能通过普通编辑权限绕过校验。

撤回必须说明原因、影响范围、是否阻止新Session和是否通知机构。历史Session仍保留解析清单。回滚不是覆盖旧版本，而是将Catalog推荐/默认指针指向已存在的安全版本；Assignment若已固定版本，不自动变更。

## 8. 资源与外部依赖安全

- 资源引用不得访问任意本地路径或内部网络地址；
- 远程资源应在发布时下载/校验并内容寻址，运行时避免不受控动态拉取；
- 文件类型、大小、像素/帧数和解压后大小有上限；
- 外部字体、图像、音频、模型和代码资产记录许可与来源；
- 生产Runtime不执行Package内自定义脚本；
- 未来Plugin必须独立签名、权限声明、隔离和审批，不能混入Package信任边界。

## 9. 兼容策略

Package apiVersion与Model/Scene/Instrument等子资源契约分别版本化。向后兼容变更必须通过旧包验证集；破坏性变更提升主版本并提供迁移工具。已发布包永不原地迁移，迁移生成新Package版本并保留来源链。

## 10. 必须测试

缺字段/未知字段；重复键；浮动引用；digest篡改；资源缺失；单位/端口不兼容；许可缺失；恶意文件和路径穿越；过大资源；撤回期间新建Session；历史Session解析；同版本不同digest冲突；旧Schema兼容；发布审批绕过测试。

## 11. 待冻结项

正式JSON Schema、归档格式、digest算法、签名与密钥轮换、语义版本规则、校验警告分级、资源大小配额、撤回策略和旧版本支持窗口须形成ADR并通过工具链Spike。
