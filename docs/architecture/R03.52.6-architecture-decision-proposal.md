## DEC-19 — Trusted Tenant Context

**Problem.** Transaction-local PostgreSQL GUC is caller-controlled state. Existing RLS policy filters rows according to the GUC but does not authenticate the tenant identity. The PostgreSQL adversarial harness intentionally demonstrates that a SQL-capable application role can change the GUC and read another tenant's row.

**Candidate.** Use application authorization based on a verified authentication principal and server-side tenant membership; persist the resolved tenant on the Job; issue a short-lived assertion bound to subject, tenant, audience, action, resource/job, expiry and nonce; validate it at an independently trusted boundary before installing transaction-local context; apply RLS and tenant-aware constraints as defense in depth. Worker Store operations additionally fence tenant/job/owner/epoch/DB-clock expiry. Plain GUC-only authorization is rejected as an adequate trust boundary.

**Alternatives.** A (application predicates only) is insufficient as sole control at scale; C (database role/credential per tenant) offers stronger identity separation but increases pool/credential/role cardinality. See the isolation-options document.

**Consequences.** More issuer/verifier and key-management complexity; every DB entry point must bind context to a transaction; issuer/verifier outage denies access. Residual compromise of issuer or privileged DB identities remains in scope.

**Approval gates.** Threat model sign-off; issuer/key custody decision; independent DB/gateway verification; missing/spoof/expiry/replay/mismatch tests; pool commit/rollback/cancellation tests; Worker cross-tenant fencing tests; SECURITY DEFINER/grant review; load/failure evidence; named approval.

**Status: OPEN.** Candidate B is PROPOSED only. HMAC Python verifier is a reference contract, not production trust establishment.

## DEC-04 — Production Store / Pool / Migration

**Problem.** Current PostgreSQL scripts are disposable integration harnesses. No production Store adapter, pool, migration lifecycle, or connection budget exists.

**Candidate.** Define language-neutral Store protocol and explicit Unit of Work. Use short bounded transactions for claim/renew/complete/fail/replay; never hold DB connections during handler execution. Separate runtime and migration identities. Adopt expand/contract migrations, immutable checksummed artifacts, migration locking, forward-fix/compensating migration and restore tests. Bound pool size, acquisition queue and timeouts; discard uncertain connections.

**Candidates to benchmark.** psycopg 3 + psycopg_pool; asyncpg + pool; SQLAlchemy 2.x async engine/pool. PostgreSQL 17 remains CI test target only. Python production runtime is not selected (DEC-03 OPEN).

**Approval gates.** Version/support policy; driver/pool benchmark; cancellation and connection-reset proof; pool exhaustion and failover tests; transaction/retry/error contract; migration interruption/restore/compatibility tests; multi-process Worker tests; observability/capacity review; named approval.

**Status: OPEN.** No driver, pool or migration tool is selected.
