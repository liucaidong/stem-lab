# R03.48 Package Archive Ingestion & Quarantine Boundary

- Version: 0.1
- Date: 2026-11-02
- Status: In-memory archive validation harness; CI pending
- Parent: R03.47
- Risks: AUD-001, AUD-002, AUD-003
- Product Code Freeze: ACTIVE

## 1. Objective

Define and test a safe archive boundary between untrusted Package upload bytes and the verified Package resource set. The harness must reject hostile archive metadata before reading payloads and must never extract entries to the runner filesystem.

## 2. Threat model

Archive bytes and all entry metadata are untrusted. Relevant attacks include:
- Zip Slip / absolute paths / Windows drive and backslash paths;
- duplicate names and case-fold collisions across platforms;
- symlink entries that redirect later writes;
- encrypted entries that bypass inspection;
- unsupported compression methods;
- decompression bombs and oversized individual/aggregate output;
- missing Manifest, undeclared resources, missing declared resources;
- byte substitution with a digest mismatch;
- malformed archive structures and CRC failures.

The harness is an archive parser gate, not malware scanning or content safety analysis.

## 3. Ingestion policy contract

Schema: contracts/package-ingestion-policy.schema.v1alpha1.json.

The fixture policy constrains:
- archive byte size;
- entry count;
- per-entry and total uncompressed size;
- maximum compression ratio;
- allowed methods (stored/deflated);
- mandatory root manifest.json;
- symlink/encryption rejection;
- case-fold collision rejection.

The limits are fixture values, not production capacity decisions. Production limits must be calibrated against package size distribution, target devices, storage costs and abuse testing.

## 4. Validation order

1. Reject archive bytes above max_archive_bytes.
2. Parse central directory; reject malformed archive.
3. Check entry count before reading payloads.
4. Validate every path, duplicate and case-fold collision.
5. Reject directory entries, symlinks, encrypted entries and unsupported compression.
6. Enforce per-entry size, aggregate uncompressed size and compression ratio from metadata.
7. Require exactly one root manifest and exact declared resource set.
8. Stream each entry from the in-memory archive with a bounded read.
9. Verify actual decompressed length, SHA-256 and exact expected bytes.
10. Rely on ZIP reader CRC validation while streaming; malformed CRC rejects.

No archive entry is written to disk. External and restricted Catalog resources are not included in this local archive and are never fetched.

## 5. Required rejection cases

The harness covers traversal, absolute paths, backslash paths, duplicate paths, case-fold collision, symlink, encrypted entry, compression ratio, entry count, entry size, missing Manifest, undeclared entry, resource digest mismatch and unsupported compression.

## 7. Security limitations

- In-memory fixture tests do not establish safety of a production archive parser under arbitrary malformed input.
- No filesystem extraction means symlink race and destination-directory attacks are prevented by omission in this harness, not tested against a real extractor.
- No object storage, quarantine bucket, antivirus/sandbox, content-type sniffing or CDR.
- No remote URL resolution, DNS rebinding/SSRF/redirect controls.
- No resource byte coverage for every Catalog entry.
- No signature/attestation or license enforcement.

A production ingestion service should use an isolated low-privilege worker, bounded streaming, private quarantine storage, immutable content-addressed objects, explicit lifecycle states, audit events, and no network egress by default. Any remote fetch must be a separate approved resolver with DNS/IP and redirect policy.

## 8. Exit criteria

R03.48 fixture scope is complete when the policy schema validates, the in-memory valid archive resolves exactly the expected Manifest/resources, all listed hostile cases reject with stable error codes, no disk extraction occurs, and CI evidence is recorded.

AUD-001/AUD-002 remain OPEN until production ingestion, all-resource byte verification, immutable storage and trust-chain integration are implemented and audited.
