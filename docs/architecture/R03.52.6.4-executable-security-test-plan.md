## 4. Additional PostgreSQL Job-boundary checks

The PostgreSQL harness also exercises a disposable `jobs` table under ENABLE/FORCE RLS:
- tenant A claim/read sees only A's persisted Job row;
- a tenant A completion predicate targeting tenant B's Job updates zero rows;
- completion with the wrong lease owner/epoch updates zero rows, while the current owner/epoch predicate updates one row.

These are SQL predicate/RLS tests against a disposable table. They are not execution through a production Store adapter, do not prove a trusted tenant assertion, and do not replace multi-process R03.52.7 integration tests.


## 8. Additional mandatory tests from approved DEC-19 target

The current GUC-spoof harness is not sufficient to validate the approved architecture. Before production enablement, add a database-side assertion verifier and prove:

- forged/modified signature rejected even when caller sets arbitrary tenant GUC;
- valid assertion only authorizes its exact tenant, subject, audience, action and resource/Job;
- cross-tenant, cross-action, cross-resource and cross-audience substitution rejected;
- expired, future-issued, revoked-key and unknown-key assertions rejected;
- nonce replay rejected where single-use semantics are required; permitted idempotent reuse is limited to the same operation and transaction scope;
- runtime role cannot SELECT/UPDATE verifier keys, replace verifier functions, disable RLS, change table ownership, grant itself privileges, or use BYPASSRLS;
- SECURITY DEFINER search_path/object-shadowing and privilege escalation attempts fail;
- assertion context is cleared after commit, rollback, cancellation, connection reset and pool reuse;
- Worker assertion cannot complete/renew another tenant's Job or a stale owner/epoch;
- verifier outage, key rotation overlap, emergency revocation and database failover fail closed.

Tests must execute against the actual chosen verifier implementation and role grants, not a Python-only mock. The current reference HMAC verifier and GUC-spoofability reproduction remain contract evidence only.


## 9. R03.52.7.1 PostgreSQL verifier spike

New executable test: `scripts/test_postgres_tenant_assertion_verifier.py`.

The test installs pgcrypto in the disposable PostgreSQL service, creates a NOLOGIN verifier-owner role and protected signing-key table, creates a fixed-search_path SECURITY DEFINER verifier, grants only EXECUTE to a non-owner/non-BYPASSRLS runtime role, and applies RLS policies that verify exact tenant/audience/action/resource claims.

Adversarial cases include valid exact-scope access, missing/forged/tampered/expired/future assertions, plain-GUC spoof attempts, resource/audience/action substitution, read-vs-update action separation, key-table read/update denial, verifier replacement denial, verifier-owner role escalation denial, and runtime role/table ownership checks.

The HMAC key is ephemeral and shared by the test issuer fixture. This is not production key custody. Nonce consumption, rotation/revocation, asymmetric verification, full privilege-path audit, connection-pool lifecycle, Worker fencing integration and named security sign-off remain open. CI outcome must be observed before marking the spike PASS.
