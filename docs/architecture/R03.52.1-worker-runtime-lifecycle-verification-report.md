## 2. R03.52.1 test coverage

1. Idle claim does not invoke a handler.
2. Successful handler requests completion using the claimed epoch.
3. Handler exception is classified through an injected safe-error classifier; raw exception text is not persisted.
4. Heartbeat false result marks lease lost and suppresses completion/failure writes.
5. Shutdown before claim prevents a new claim.
6. Shutdown during active work allows cooperative drain and preserves the shutdown signal in JobContext.
7. Heartbeat transport exception fails closed as lease loss.
8. Missing handler fails closed as a non-retryable configuration error.
9. Heartbeat interval equal to or greater than lease duration is rejected.

## 3. What this proves

The reference runtime correctly orchestrates one claimed job at a time, dispatches by job type, renews a lease in a background heartbeat, treats renewal failure as lease loss, avoids local completion/failure writes after lease loss, and stops taking new work after shutdown request.

The Store remains the authority. Every production Store mutation must independently validate tenant, job ID, lease owner, epoch and database-clock expiry.

## 4. What this does not prove

- No production PostgreSQL Store adapter or trusted tenant-context issuer.
- No production database migration or connection-pool isolation.
- No OS signal adapter, process supervisor, container health check or restart policy.
- No bounded shutdown guarantee for non-cooperative handlers.
- No multi-slot concurrency, tenant fairness or Scheduler service.
- No real Broker/Outbox relay, consumer or DLQ replay.
- No handler sandbox, CPU/memory quota or external side-effect fencing.
- No production metrics, tracing, alerting or SLO.

A fake Store unit test cannot prove DB transaction/fencing semantics. R03.51 PostgreSQL tests remain separate evidence for the disposable reference schema only.
