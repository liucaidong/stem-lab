# R03.15 Runtime状态迁移矩阵与Command行为规范

- 版本：0.1；日期：2026-11-02
- 状态：详细契约草案；待状态机单测与并发Spike
- 关联：R03.7、R03.14、R03.10

## 1. 状态集合

持久化Session状态：created、ready、running、paused、completed、failed、cancelled。resuming不是Session持久化状态。Execution状态独立：queued、leased、running、succeeded、failed、timed_out、cancelled、rejected。

## 2. 迁移矩阵

| 当前状态 | 命令/事件 | 下一状态 | 条件 | 副作用 |
|---|---|---|---|---|
| created | Initialize成功 | ready | Package/Model依赖和初始值校验通过 | 固定依赖快照、写初始化事件 |
| created | Initialize失败 | failed | 不可恢复初始化错误 | 记录错误和审计 |
| ready | Start | running | 授权、配额和输入有效 | 创建Execution |
| ready | Step | paused | 单步成功 | 仅推进一个step unit和Simulation Clock |
| ready | Cancel | cancelled | 主体有取消权限 | 关闭启动入口 |
| running | Pause | paused | 在安全提交边界完成 | 停止新调度 |
| running | Step | running | 仅内部执行策略或明确允许 | 推进单个step；不可并发双Step |
| running | Complete | completed | 模型终止条件/任务规则满足 | 固定最终Snapshot |
| running | FatalFailure | failed | 不可恢复错误 | 保留最近有效状态 |
| running | Cancel | cancelled | 授权取消且取消边界完成 | 递增epoch，拒绝迟到结果 |
| paused | Resume | running | 输入状态有效、配额允许 | 新Execution/新lease |
| paused | Step | paused | 单步成功 | 更新状态和Simulation Clock |
| paused | Reset | ready | Reset策略允许 | 恢复初始状态，epoch递增 |
| ready | Reset | ready | 幂等重置 | 恢复初始状态，版本递增 |
| failed | Reset | ready | 失败类型允许恢复 | 创建新Execution lineage |
| completed | 任意写命令 | completed | 不允许 | 返回终态错误 |
| cancelled | 任意写命令 | cancelled | 不允许 | 返回终态错误 |

注意：Step的目标状态在ready/paused下保持原状态；Step只有在结果通过验证后才提交。Reset不删除历史事件、Observation和Snapshot。

## 3. Command行为矩阵

| Command | 允许状态 | 权限 | 幂等/版本 | 主要副作用 |
|---|---|---|---|---|
| Initialize | created | Session owner/系统 | Idempotency-Key | 初始化状态、依赖检查 |
| Start | ready | Attempt owner | Key + stateVersion | 创建Execution |
| Pause | running | Attempt owner/教师按策略 | Key + stateVersion | 停止后续调度 |
| Resume | paused | Attempt owner | Key + stateVersion | 创建新Execution/lease |
| Step | ready/paused | Attempt owner | Key + stateVersion | 单步求解和状态提交 |
| Reset | ready/paused/failed | Attempt owner/教师策略 | Key + stateVersion | 初始状态恢复、epoch递增 |
| Cancel | 非终态 | Owner/教师/管理员策略 | Key + stateVersion | 取消调度、fencing |
| SetParameter | ready/paused | Owner | Key + stateVersion | 参数校验和新状态版本 |

具体角色策略由Assignment和Tenant Policy限制。教师不能默认越权操作学生Session；必须有明确的课程授权和审计。

## 4. 不变量

1. Session的state_version单调递增。
2. aggregate_sequence单调递增。
3. 只有Command Handler/Result Commit Handler可变更权威状态。
4. 同一Session同一时刻最多有一个有效推进Execution，除非模型显式声明并行分支语义。
5. 只有匹配epoch、lease、execution和input_state_version的结果可提交。
6. Simulation Clock只在有效结果提交时推进。
7. Reset递增epoch并使旧Worker结果失效。
8. 完成/取消是终态；重新实验创建新Attempt/Session。
9. 幂等重放不重复产生状态、事件、Observation或外部副作用。
10. UI显示状态以服务端Read Model为准。

## 5. 并发与竞态处理

Pause与Result Commit竞态：由Session事务锁和版本检查决定线性化顺序。若结果先提交，Pause针对新状态生效；若Pause先完成，旧执行结果须按Pause策略提交或拒绝，不得出现状态倒退。

Reset与Worker提交竞态：Reset递增epoch；旧Worker提交必然被拒绝。

Cancel与Worker提交竞态：Cancel递增epoch并关闭执行授权；迟到结果拒绝。

重复Start竞态：相同幂等键返回原Receipt；不同键但状态已running的请求返回稳定状态冲突，不创建第二个有效Execution。

## 6. 错误码候选

SESSION_NOT_READY、SESSION_TERMINAL、INVALID_STATE_TRANSITION、STATE_VERSION_CONFLICT、IDEMPOTENCY_KEY_REUSE_CONFLICT、EXECUTION_LEASE_EXPIRED、STALE_EPOCH、EXECUTION_INPUT_MISMATCH、SOLVER_OUTPUT_INVALID、QUOTA_EXCEEDED、COMMAND_NOT_ALLOWED_BY_PACKAGE。

错误码必须稳定、可文档化，不包含内部堆栈或敏感资源信息。

## 7. 测试向量

- 每一条允许迁移至少一条正向测试；
- 每一条禁止迁移至少一条负向测试；
- 同Key同Hash、同Key异Hash、不同Key相同命令；
- 两个客户端同时提交同一stateVersion；
- Pause/Reset/Cancel与Worker结果同时到达；
- Worker过期lease和旧epoch；
- Reset后历史Observation仍可查询；
- Step失败不推进Simulation Clock；
- 终态Session拒绝写入；
- 重复消息不产生二次副作用。

## 8. 待冻结项

Reset是否允许在running状态、教师对学生Session的控制权限、Step粒度、Pause对在途任务策略、执行重试次数和错误恢复策略需由产品/架构共同批准，并更新状态机测试。
