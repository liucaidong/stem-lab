# R03.11 多租户身份、安全边界与威胁模型基线

- 版本：0.1；日期：2026-11-02
- 状态：安全设计基线；需专业安全与法律审查
- 关联：R02.3 FR-IAM/FR-OPS/FR-AI、R03.6 TF-08/12

## 1. 安全目标

保护学生和机构数据；防止跨租户访问、权限提升、Runtime状态伪造、Worker越权、Package供应链攻击、AI工具越权和敏感信息泄露。安全必须在API、数据库、后台任务、对象存储、消息消费和运营工具各层执行，不能只依赖前端。

## 2. 信任边界

- Public Client：浏览器/客户端不可信；
- API/BFF：验证身份、构建可信主体和Tenant上下文；
- Domain Application：执行资源授权和业务规则；
- PostgreSQL：事务和RLS强制隔离；
- Event Bus：异步消息边界，消息内容需校验；
- Worker Sandbox：执行不可信输入但不拥有业务数据库权限；
- Object Storage：文件和大体积数据，需独立访问授权；
- AI Gateway：工具调用的唯一受控入口；
- Admin/Ops Plane：高权限操作需独立角色、审批和审计。

## 3. 身份与授权

认证优先支持OIDC，机构联邦可按需求支持SAML。外部身份映射为平台内部User/Identity，不直接以邮件地址作为永久主键。

授权采用RBAC与ABAC组合：
- RBAC定义角色能力；
- ABAC约束Tenant、课程归属、Assignment、资源所有者、数据敏感级别和操作上下文；
- 默认拒绝；
- 权限在服务端每次请求校验；
- 管理员权限分机构范围和平台范围；
- 平台运营访问租户数据必须有工单/目的/时限和审计。

## 4. Tenant Context与RLS

Tenant Context必须来自已验证的认证/映射上下文，不能由请求参数决定。数据库事务开始时使用transaction-local tenant context；连接池复用时确保事务结束清理上下文。RLS对所有租户业务表启用并强制；应用角色不得BYPASSRLS，不得拥有绕过策略的表所有者权限。

后台任务必须携带经过签名/验证的tenant和任务范围，不能从不可信消息payload直接信任tenant_id。跨租户平台作业使用独立受限服务身份，并显式声明目的和允许的数据集。

## 5. Worker与计算隔离

Worker默认非root、只读基础镜像、CPU/内存/时间/临时磁盘限制、网络默认拒绝、无生产数据库凭证、无宿主机挂载。输入为不可变快照；输出经过Schema、大小、单位、范围和digest校验。Solver依赖锁定版本并扫描供应链风险。

若未来引入用户脚本或Plugin，必须独立威胁建模、沙箱逃逸评估、权限清单、签名验证和资源限制；不能沿用普通Worker的信任级别。

## 6. Package与文件安全

Package和资产视为不可信：限制文件类型、压缩比、文件数、大小、路径规范和解析深度；阻止路径穿越、Zip Slip、恶意SVG/HTML脚本、远程资源SSRF、内部IP探测和不安全重定向。发布前扫描依赖、许可和来源。生产Runtime不执行Package任意代码。

## 7. AI Tool Gateway安全

AI不直接持有数据库凭证、任意Shell/Python权限或设备控制权限。Tool Gateway执行：
- 委托主体身份和Tenant校验；
- 工具白名单、参数Schema和资源范围校验；
- 最小权限和速率/预算限制；
- 高影响操作的用户确认；
- 工具调用、结果和拒绝原因审计；
- 敏感字段最小化和输出过滤。

AI生成的解释不是科学事实来源；结论必须引用可见Observation/模型版本。自动评价不得在证据不足时生成正式评分。

## 8. 数据保护与隐私

建立数据目录，逐项记录数据主体、字段、目的、来源、处理者、存储区域、保留期、访问角色、共享对象和删除方式。默认最小化采集；日志避免记录学生正文、令牌和敏感数据。支持按适用法规执行访问、更正、导出和删除请求。

上线前必须确认目标地区和法域，评估未成年人数据、学校角色、监护人授权、数据跨境、供应商DPA、数据驻留、备份保留和AI供应商数据处理。不得在未经独立授权和审批的情况下将生产学习数据用于模型训练。

## 9. 威胁登记（初版）

| 威胁 | 攻击路径 | 控制措施 | 验证 |
|---|---|---|---|
| 跨租户IDOR | 修改资源ID | Tenant/资源授权、RLS | API与DB负向测试 |
| 权限提升 | 伪造Role/Claim | 服务端身份映射、默认拒绝 | 权限矩阵测试 |
| Worker伪造结果 | 伪造Execution/epoch | 短期凭证、fencing、结果校验 | 迟到/伪造结果测试 |
| Package恶意文件 | 上传脚本/压缩炸弹 | 文件扫描、解析限制、禁止执行 | 恶意样本测试 |
| SSRF | Package引用内网URL | 资源代理、地址过滤、无运行时任意抓取 | 网络隔离测试 |
| AI越权 | Prompt诱导调用高权限工具 | Tool白名单、委托权限、审批 | 红队用例 |
| 事件重放 | 重放消息造成重复副作用 | event_id幂等、序列号校验 | 重复/乱序测试 |
| 对象存储泄露 | 猜测URL或权限配置错误 | 短期签名URL、对象级授权 | 权限与过期测试 |
| 敏感日志泄露 | Token/学生数据进入日志 | 脱敏、字段白名单、访问控制 | 日志扫描 |
| 供应链攻击 | 恶意依赖或镜像 | 锁文件、镜像签名/扫描、SBOM | CI安全检查 |
| 备份暴露 | 备份权限或密钥失控 | 加密、隔离、访问审计 | 恢复演练与权限审计 |

## 10. 安全验证门禁

威胁建模；API授权测试；PostgreSQL真实RLS和连接池复用测试；对象存储权限测试；Worker网络隔离测试；Package恶意输入测试；依赖与容器扫描；Secret扫描；AI工具越权测试；日志脱敏测试；备份恢复和删除请求演练。高风险问题关闭前不得进入真实学生数据试点。
