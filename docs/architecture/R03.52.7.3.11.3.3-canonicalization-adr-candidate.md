# ADR Candidate — Request Digest Canonicalization v2alpha2

**Status:** OPEN / CANDIDATE ONLY / NOT APPROVED

## Decision question

Select an encoding that signer, Python Runtime and PostgreSQL can independently reproduce byte-for-byte.

## Options

| Dimension | RFC 8785 JCS | Versioned Typed Encoding |
|---|---|---|
| Standardization | Published JSON standard | Project-specific frozen protocol |
| Interoperability | Broad implementations; conformance still required | Every implementation implements the same small codec |
| PostgreSQL recomputation | Difficult: jsonb normalization and numeric rendering are not JCS | Feasible with bytea, explicit tags, UTF-8 and length prefixes |
| Numeric model | IEEE-754 binary64 constraints | Integer-only signed int64; decimal quantities use integer base units |
| Unicode | Defined JSON string serialization | Exact UTF-8; reject unpaired surrogates; no NFC/NFD folding |
| Duplicate keys | Must reject before canonicalization | Must reject before lossy jsonb conversion |
| Arrays | Preserve order | Preserve order |
| Null/absent | Distinct | Distinct tags / omitted object member |
| Complexity | Moderate in app languages, high in PostgreSQL | Moderate if action argument types remain narrow |
| Extensibility | Generic JSON values | New value types require version governance |

## Candidate recommendation

Recommend Versioned Typed Encoding, conditional on a PostgreSQL proof-of-equivalence. This is not an approved ADR.

The current operation arguments are narrow enough to use strings, booleans, arrays/objects and signed int64. Floating-point values are prohibited. Retry delay is represented as integer microseconds in the signed envelope. The database must calculate the digest from actual typed parameters, never accept a caller-provided digest as proof.

## Candidate byte format

Domain prefix: ASCII/UTF-8 bytes STEMLAB-REQUEST-DIGEST followed by NUL, v2alpha2, NUL.

Fixed envelope field order:
contract_version, action, tenant_id, job_id, session_id, resource_type, resource_id, operation_id, idempotency_key.

Each field: byte 0x53 (S), uint32 big-endian UTF-8 byte length, exact UTF-8 bytes.

Then operation_arguments: byte 0x4A (J), uint32 big-endian encoded-value length, recursively encoded typed value.

Value tags:
- N: null
- F / T: boolean false / true
- I: signed integer encoded as canonical base-10 ASCII with uint32-BE length
- S: UTF-8 string with uint32-BE length
- A: uint32-BE item count followed by values in original array order
- O: uint32-BE member count followed by key/value pairs sorted by raw UTF-8 key bytes; each key has uint32-BE byte length

Limits: nesting depth 32; array/object count 4096; signed int64; lengths fit uint32. Reject floats, NaN, infinities, invalid UTF-8, unpaired surrogates and duplicate keys. No Unicode normalization: canonically equivalent NFC/NFD strings remain distinct.

Digest claim: sha256: plus 64 lowercase hexadecimal SHA-256 digits (71 ASCII characters). Hash the exact canonical bytes.

## Required PostgreSQL proof

1. Receive actual typed function parameters and raw argument representation, not a runtime digest.
2. Reject duplicate JSON keys before conversion to jsonb.
3. Enforce action-specific argument schemas and integer-only numeric values.
4. Construct bytea using the same fixed order, UTF-8 bytes and network-order lengths.
5. Use a pinned and verified database SHA-256 function.
6. Compare against the signed request_digest before nonce insert or business mutation.

If PostgreSQL cannot prove byte equality, stop and reopen this ADR. No fallback to jsonb text, caller digest trust or GUC-only authorization.

## Compatibility

- v2alpha1 remains byte-for-byte and semantically unchanged.
- v2alpha1 is never treated as v2alpha2.
- v2alpha2 requires request_digest and idempotency_key.
- Unknown versions and missing digest fail closed.
- This ADR remains OPEN until Python/PostgreSQL vectors match and Architecture/Security formally approve it.
