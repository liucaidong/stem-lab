## States

| State | Meaning | Lease fields | Terminal |
|---|---|---|---|
| queued | durable and waiting for availability | null | no |
| running | claimed by one owner/generation | owner + expiry | no |
| retry | retryable failure scheduled | null | no |
| succeeded | fenced completion committed | null; completed_at set | yes |
| dead_lettered | permanent failure or attempts exhausted | null | yes |
| cancelled | authorized cancellation | null | yes |

The schema enforces that only running jobs carry owner/expiry and only succeeded jobs carry completed_at. One active Job per Session/Job Type is enforced by a partial unique index.

## Transition guards

| From | To | Trigger | Guard |
|---|---|---|---|
| queued | running | claim | due; row lock; attempt capacity |
| retry | running | claim | available_at <= DB clock |
| running | running | reclaim | lease expired; epoch increments |
| running | retry | failure | owner/epoch match; lease valid; attempts < max |
| running | dead_lettered | failure | non-retryable or attempts >= max |
| running | succeeded | completion | owner/epoch match; lease valid; expected Session revision |
| queued/retry | cancelled | operator | authorized action; not implemented |

## Epoch and attempt semantics

Epoch starts at zero and increments by one on every successful claim/reclaim. It is not reset by retry, restart or DLQ. Attempt count increments once in claim transaction. A retry transition does not increment it again. A crash after claim consumes the attempt. At maximum attempts, another retry is prohibited.

## Idempotency

- Scheduling uses a stable caller idempotency key plus the active-job uniqueness constraint.
- Claim is serialized by row lock and SKIP LOCKED.
- Completion is fenced by tenant, job, owner, epoch and lease expiry.
- Same-epoch duplicate completion after success is a no-op; it cannot append a second Session Transition or Outbox event.
- Old epochs and wrong owners are rejected.

## Retry formula

For n >= 1, b_n = min(b_max, b_0 * 2^(n-1)); full jitter is Uniform(0, b_n). Persist available_at in the same transaction as the running-to-retry transition. The current reference helper accepts the computed delay from its caller; central policy registry remains OPEN.

## DLQ and replay

DLQ stores original Job identity, attempt count, terminal reason, epoch and safe error metadata. Manual replay is not implemented. Future replay must create a new Job, require permission and audit actor/reason, preserve original DLQ evidence and enforce a replay limit.
