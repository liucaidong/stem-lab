# R03.52.7.3.11.3.10 — Request Digest Threat Model & Residual Risk Register

**Status:** PARTIAL / OPEN / NO PRODUCTION ACCEPTANCE

## 1. Assets and trust boundaries

Assets: tenant isolation, Job/Session ownership and lease fencing, resource identity, state transitions, Receipt uniqueness, Nonce replay protection, Transition history, Outbox delivery intent, signing key integrity and audit evidence.

Trust boundaries:
- trusted request normalizer and Assertion signer;
- untrusted or compromised Runtime process;
- PostgreSQL verifier and transaction boundary;
- database roles, SECURITY DEFINER owners and RLS policies;
- asynchronous Outbox publisher and downstream consumer.

## 3. Required persisted-state assertions

Every adversarial database test must snapshot and compare:
- Job status, owner, epoch, lease and session revision;
- Nonce Ledger rows;
- Receipt rows and stored digest;
- Transition rows;
- Outbox rows and dispatch state;
- DLQ rows where applicable.

A thrown exception alone is insufficient evidence. A mismatch must leave every listed table unchanged. Same-key/different-digest must return the defined conflict and leave business state unchanged. Same-key/same-digest must return the original Receipt and must not duplicate Transition or Outbox rows.

## 4. Current residual risk

The critical risks are not the SHA-256 primitive or Python encoder. They are the absence of a trusted signer path, absence of a raw-claim duplicate-key verifier, lack of handler integration, incomplete Receipt uniqueness semantics, and unproven outer transaction rollback under false/null/exception paths.

Do not treat the current reference helper tests as authorization-boundary acceptance. R535-OD3 remains OPEN until these risks are closed and formal Architecture/Security approval is recorded.
