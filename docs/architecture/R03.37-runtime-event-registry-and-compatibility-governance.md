# R03.37 Runtime Event Registry 与 Compatibility Governance

- 版本：0.1；日期：2026-11-02
- 状态：CI Run #113通过Registry与兼容性静态验证（局部）；未覆盖完整事件目录，未实现Broker/Consumer
- 关联：R03.10、R03.20 DEC-05/DEC-30、R03.26、R03.32

## 1. 目标与边界

将event_type + schema_version作为事件契约的稳定寻址键。Registry同时登记Payload Schema、Producer/Consumer、聚合顺序范围、Replay策略、保留期、数据分类、Poison Event策略和生命周期。Registry验证不能证明事件已提交、消费者幂等或Broker可靠性。

## 2. Registry记录

每个事件定义包含：
- event_type、schema_version、payload_schema、fixture；
- lifecycle：proposed / active / deprecated / retired；
- compatibility：initial / additive / breaking及compatible_with；
- producer_ids、consumer_ids；
- ordering_scope：aggregate / unordered；
- replay_policy：allowed / forbidden / requires-approval；
- retention_days、data_classification；
- poison_policy：max_attempts、retry_strategy、dlq_required；
- deprecated_at、sunset_at、replacement_event（仅生命周期需要时）。

唯一键是(event_type, schema_version)。同一event_type可有多个并行版本，但每个版本只能有一个Schema定义。

## 3. Versioning与Compatibility规则

- 初始版本change_class=initial，不声明compatible_with。
- Additive版本必须增加minor且major保持一致；只允许新增可选字段/不改变既有语义。严格Schema Consumer可能拒绝未知字段，因此需显式Consumer兼容性矩阵或Upcaster。
- Breaking版本必须提升major；删除/重命名字段、改变字段含义、必需性或枚举语义均视为Breaking。
- 未知event_type或schema_version必须拒绝或隔离，不得按“最接近版本”猜测解析。
- Deprecated必须有deprecated_at和sunset_at，并声明replacement_event（若有）；Retired版本不得由新Producer发布，但历史事件仍需按保留/审计策略读取。

当前版本字段使用major.minor字符串，尚未声明完整SemVer patch语义。

## 4. Producer / Consumer Contract

Producer必须在Registry列出，并受服务端权限控制；Consumer必须声明订阅事件和数据分类授权。Registry声明本身不是权限授予。每个事件还需定义聚合顺序、租户上下文来源、最大Payload大小和敏感字段治理（后续补充）。

## 5. Replay、Retention与Poison Event

- Replay策略分allowed、forbidden、requires-approval；requires-approval必须关联审计审批和隔离重建Consumer。
- Retention是事件/Envelope的保留天数，不自动决定Observation/Asset数据保留。
- Poison Event需有界重试、失败分类、DLQ或隔离策略；禁止无限重试或静默丢弃。
- DLQ访问必须按Tenant和数据分类授权；重放需保留原event_id/causation信息并防止副作用重复。

## 6. 当前Registry覆盖

目前只登记SessionStarted、ExecutionSucceeded、ObservationRecorded三种代表事件。R03.10中其他Runtime状态、Command、Package、Submission和Assessment事件仍未注册。新增事件必须提供Schema、Fixture、Producer/Consumer和治理元数据。

## 7. 自动化资产

- contracts/events/registry.schema.v1alpha1.json；
- contracts/events/registry.v1.json（扩展治理元数据）；
- contracts/examples/event-registry.validation.fixtures.v1alpha1.json；
- scripts/validate_event_registry.py。

脚本校验Schema、唯一键、兼容性声明、生命周期、Producer/Consumer元数据和对应Payload Schema/Fixture。它不测试真实Producer、Consumer、Inbox、Outbox或Broker。
