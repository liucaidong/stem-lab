## 1. 目标与边界

把R03.27物理模型/RLS草案推进为可执行PostgreSQL集成测试。测试覆盖RLS、事务回滚、复合外键、幂等唯一键、Inbox去重、Outbox并发claim和事务本地Tenant Context清理。CI测试服务使用PostgreSQL 17；这只是测试环境，不代表生产数据库主版本或迁移工具已选定。

## 2. Tenant Isolation

RLS应用于所有tenant-owned表，ENABLE + FORCE；策略使用事务本地app.tenant_id并同时定义USING/WITH CHECK。普通应用角色不得拥有BYPASSRLS。tenant-owned外键使用(tenant_id,parent_id)复合键，防止跨租户关系。

重要安全边界：自定义GUC可由拥有数据库会话权限的应用角色设置。它可防止查询遗漏Tenant过滤，但不能抵御已被攻陷的应用数据库凭证或任意SQL执行。必须同时使用服务端身份验证、参数化SQL、最小权限、禁止客户端直连，并评估更强隔离方案。DEC-19继续OPEN。

## 3. Transaction / Messaging

Command状态更新与Outbox写入必须在同一数据库事务；失败全部回滚。Inbox使用(tenant_id,consumer_id,event_id)唯一键，payload_digest不一致必须触发完整性异常。Outbox Relay通过FOR UPDATE SKIP LOCKED并发领取，发布与published标记之间仍可能重复，Consumer必须幂等。

## 4. 可执行测试

脚本：scripts/test_postgres_transaction_rls.py
CI服务：PostgreSQL 17临时容器；连接驱动候选psycopg 3.3.6。

测试覆盖：
- RLS Tenant A/B隔离；
- 缺失Tenant Context默认无行；
- WITH CHECK拒绝跨Tenant写入；
- Composite FK拒绝跨Tenant关联；
- Transaction-local GUC连接复用不泄漏；
- Command State与Outbox原子回滚；
- Idempotency Key唯一约束；
- Inbox重复去重和Digest冲突；
- Outbox SKIP LOCKED并发claim；
- Inbox/Outbox自身的Tenant RLS。
