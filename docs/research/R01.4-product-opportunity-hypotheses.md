# R01.4 竞品差距与产品机会假设

- 文档编号：R01.4
- 版本：0.1
- 日期：2026-11-02
- 状态：假设清单，尚未作为最终产品决策

## 1. 核心判断

公开市场呈现出多种相邻但不同的产品形态：
- 虚拟实验产品擅长实验内容、场景交互和学习评价；
- 科学模拟产品擅长概念可视化和参数探索；
- 科学建模产品强调模型构建、操纵与证据比较；
- 专业工程仿真产品强调数值求解、工程验证和计算资源；
- 内容平台强调资源聚合、课程路径和课堂组织；
- AI 探究评价产品强调过程性行为分析和个性化反馈。

**待验证的产品机会**不是简单把这些产品拼在一个门户中，而是建立统一的模型与实验资产体系，让不同学科模型、仿真引擎、渲染器、数据工具和 AI 能力可以在同一实验契约下组合。

当前没有足够公开证据证明“市场上不存在”具备上述能力的产品。此处是本项目的差异化研究假设，不是市场事实。

## 2. 机会假设清单

| ID | 机会假设 | 目标问题 | 初步产品方向 | 风险 | 验证方式 |
|---|---|---|---|---|---|
| H01 | 统一 Scientific Model Contract | 模型、参数、单位、方程和观测变量分散 | 跨学科模型 schema、单位系统、模型版本和验证规则 | 过度抽象，首期难落地 | 以电路、力学、热学三个模型验证表达能力 |
| H02 | 独立 Simulation Runtime | 教学交互、数值计算和渲染生命周期耦合 | Session、Clock、Scheduler、Solver、State、Event 分层 | 运行时复杂度和一致性成本 | RC Circuit 验证暂停/恢复/步进/重置/重放 |
| H03 | 声明式 Experiment Package | 实验内容难复用、难验证、难跨渲染器 | Manifest + Model + Scene + Instruments + Workflow + Assessment | schema 演化和兼容性复杂 | 同一实验包至少由两种呈现方式加载 |
| H04 | 多模态实验交互 | 不同学科需要不同的图形、仪器和空间交互 | 2D/3D Renderer、仪器组件、交互物理与无障碍适配 | 视觉技术投入大 | 先完成电路图、仪表、曲线图，再验证 3D 场景 |
| H05 | 可追溯科学数据 | 实验结果缺乏来源、参数和过程上下文 | Observation、Dataset、Run Metadata、Event Trace、Export | 数据量、隐私和保留成本 | 同一实验运行可复现、导出并追溯模型版本 |
| H06 | AI 探究与实验 Agent | AI 辅导和真实实验执行之间存在安全边界 | Tutor、Copilot、Authoring Assistant、受控 Agent Orchestrator | 幻觉、越权、错误实验操作 | 工具白名单、审批策略、仿真验证、全程审计 |
| H07 | 教学评价与科学评价统一 | 只评答案不能评科学过程 | 概念掌握、实验设计、变量控制、数据解释、论证能力 | 评价效度难证明 | 设计可解释 rubric，并与专家评分对照 |
| H08 | Remote Lab 与 Digital Twin | 虚拟实验与真实设备/数据割裂 | Device Adapter、设备状态、远程操作队列、数字孪生状态同步 | 硬件异构、网络安全、实验室运维 | 先定义设备协议和模拟设备，再接单一真实设备 |
| H09 | 开放插件生态 | 模型、仪器、求解器、内容扩展成本高 | Plugin Manifest、Capability API、Sandbox、签名与权限 | 供应链和安全风险 | 首期只开放受限内容/仪器插件，不开放任意执行 |
| H10 | 跨学科项目式学习 | 单一学科模拟难表达真实工程问题 | STEM Project、跨学科依赖、团队任务和成果集 | 内容制作成本高 | 以能源系统/智能温室等项目验证 |

## 3. 产品定位工作稿

**工作定位：** 一个以科学模型和实验包为核心、以可验证仿真运行时为执行基础、以交互式可视化和数据证据为学习界面、以 AI Agent 和真实设备连接为扩展能力的综合 STEM 实验平台。

这不是最终品牌定位。还需通过目标用户访谈、竞品试用、课程标准分析和 MVP 验证。

## 4. 首个 MVP 建议

### 教学 MVP：DC Circuit & Ohm's Law

首个教学场景应闭环覆盖：
1. 概念目标与先备知识；
2. 电路元件、导线、开关、电源、电阻；
3. 可视化电路连接；
4. 电压、电流、电阻测量；
5. 欧姆定律与模型参数；
6. 实验任务、预测、操作和观察；
7. 实时曲线/数值数据；
8. 实验记录与结论；
9. 自动检查与解释性评价；
10. 教师端查看实验过程和结果。

### 技术验证案例：RC Circuit

RC Circuit 用于验证：
- ODE 模型表达；
- 数值 Solver；
- Simulation Clock 与 Fixed-step；
- Scheduler/Worker 生命周期；
- Pause/Resume/Reset/Step；
- stateVersion/epoch fencing；
- Observation 与事件轨迹；
- 结果校验和确定性重放。

教学 MVP 与技术验证案例是不同验收目标，不应混成一个范围。

## 5. 明确暂不纳入首期

- 通用 CFD/FEA/多物理场专业求解；
- VR/AR 全设备支持；
- 多品牌真实实验设备接入；
- 任意用户代码直接进入主 Runtime；
- 无限制自主 Agent 执行；
- 大规模内容市场与第三方插件审核体系；
- 完整 Digital Twin 平台。

这些是后续路线方向，不是首期交付承诺。

## 6. 进入 PRD 前必须回答的问题

1. 首期目标用户优先级：初中、高中、大学、教师/实验室，如何排序？
2. 首期课程标准与语言范围：以中国大陆课程标准为主，还是国际标准并行？
3. 产品形态：Web 优先，是否要求桌面端/平板端？
4. 首期学科边界：物理电学作为单一切入，还是同步包含化学/生物内容？
5. 内容生产模式：内部作者、教师创作、第三方机构，谁是首批内容供给方？
6. 机构采购与个人用户是否都属于首期商业目标？
7. 云端仿真、浏览器本地仿真和混合执行的首期边界？
8. 数据隐私、未成年人保护、学校租户隔离和数据驻留要求？
